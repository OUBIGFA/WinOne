# 安装与覆盖更新

开发包和正式版使用同一正常安装流程，不区分用户配置或设置“测试版不支持升级”的限制。默认程序目录为 `%LOCALAPPDATA%\Programs\WinOne`，配置、账号与偏好统一位于 `%LOCALAPPDATA%\WinOne`。程序目录可改，配置目录不随安装包版本变化；自动化测试通过显式参数使用隔离配置。

安装器和卸载器先通过 `GetUserDefaultUILanguage` 读取 Windows 当前用户的显示语言，再显示第一页或错误提示。中文使用简体中文资源，英文及尚无翻译的语言使用英文资源；不先弹出手动语言选择窗口，不沿用上次安装语言覆盖当前系统显示语言。

安装器遇到登记、目标目录已有内容或残留快捷方式时，调用 `build/installer-update` 的 `InstallCurrentPackage` 自包含修复入口。当前安装包决定最终程序内容；不要求旧安装包、旧清单、旧登记或 `.update-*` 事务可读。支持同版本重装、不同版本覆盖，以及缺失/损坏程序和中断安装的补齐。自动更新仍使用 `ExecuteUpgrade` 的严格版本、配置兼容与日志恢复规则，和用户主动运行安装包分开。

向导打开时读取的安装目录只用于预填。执行前必须重新读取当前安装登记，避免旧版在向导打开期间完成卸载后，仍把已删除的目录交给覆盖更新程序。目录和登记若在执行中再变化，后续维护锁与文件校验继续拒绝不一致状态。

手动安装流程：校验当前载荷 → 获取安装/配置维护锁并检查目标进程已退出 → 备份实际将覆盖的字节及登记/快捷方式 → 原子逐文件替换 → 使用新程序和隔离临时配置检查 Host/Worker/界面 → 重建登记与快捷方式 → 清除未完成标记。旧配置不做安装前兼容门槛，不迁移、不重置、不执行旧程序或旧恢复脚本；配置本身损坏仍由应用配置恢复处理，不能把程序安装成功说成配置已经修复。

安装目录上级是 Windows 目录链接时先解析真实路径，在真实目录旁创建唯一 `.install-*` 备份目录。`before.json` 记录原文件哈希/缺席状态、原登记、快捷方式和旧 pending；`before/` 保存被替换的实际字节；`current.zip` 保存当前校验载荷。旧 `.update-*` 和 `.install-*` 目录不扫描、不改名、不删除，因此旧包绑定、损坏历史和不同配置路径不会再阻止当前安装。

本次失败会按真实原字节回滚；进程被终止后保留 pending 和备份，下一次直接运行当前或更新安装包即可，不需要 `/REPAIR`、旧包或手动删除恢复目录。普通安装不再弹出“修复/继续卸载”选择，也不会因旧卸载记录把安装动作变成卸载。显式 `/REPAIR`、`/FINISHUNINSTALL` 保留原兼容校验，但不再是正常重装的必需入口。

只覆盖当前包拥有的文件；过期文件仅在安全路径且仍匹配旧清单哈希时移除，未知或已修改的额外文件保留。活动进程、真实写入失败、文件占用、目录链接/文件类型冲突等安全问题仍报错并保留备份，不伪造成功。

卸载时，管理员授权任务若通过完整结构校验但属于另一个 WinOne 安装目录，则予以保留。它与损坏、被修改的任务分开处理。正常启动仍严格校验当前安装入口，不能借另一目录的任务执行任意提权命令。

本地验收必须执行安装器本身：安装旧包 → 保留旧 `.update-27` 准备记录 → 安装同版本不同内容新包 → 再次安装相同包 → 卸载，并另测启动失败回滚后卸载。底层单测不能代替该入口流程。`build/test-installer.ps1 -TestSelfContainedRepair` 组合验证残留事务、登记/清单/卸载器缺失、截断程序与损坏配置；Go 行为回归另测 prepared/applying/restoring、强制终止后换包重装、文件占用和 junction 外部文件保护。

依据与范围：沿用 [NSIS 安装器命令行约定](https://nsis.sourceforge.io/Docs/Chapter3.html#installerusage) 和现有 NSIS 构建路线；显式修复按 [Windows Installer REINSTALLMODE](https://learn.microsoft.com/en-us/windows/win32/msi/reinstallmode) 的强制补齐文件、重写登记与快捷方式语义设计，但不引入 MSI 或复制其实现。程序数据使用 Windows 当前用户的 Local App Data。清单摘要用于完整性验证，不作为发行者签名。
