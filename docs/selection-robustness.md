# 划词通用读取（2026-11-15）

目标：按来源提供的选区能力取词，覆盖消息列表、自绘正文、标准输入框及浏览器。不使用软件名称、路径、窗口类或即时光标形状决定复制资格。已有用户主动设置的应用排除仍保留。

## 原因

本机 AyuGram 版本为 7.2.9。对应上游消息区域把消息暴露为 `QAccessible::ListItem`，子项为 `Cell`，选中文字通过 `QKeySequence::Copy` 交给 `copySelectedText()`。原读取器仅允许若干文本控件类型，或当前光标为 I-beam 的容器进入兼容复制，因此这类可正常复制的消息区域会被拒绝。

另一个独立问题是鼠标目标与键盘焦点的读取结果混在一起：目标缺少选区接口时，另一个焦点控件的 `empty` / `unrelated` 可覆盖它，阻止后续取词。单独增补一个软件名称不能修正这两个控制点。

## 当前流程

1. 在独立读取进程中核对前台窗口、进程、焦点和鼠标起止点的归属；检查候选路径的密码属性。来源失效或敏感字段立即停止。
2. 按鼠标起点、终点、焦点收集并去重候选路径。优先读取明确的 UIA 选区；该路径没有选区能力时，再读取旧无障碍接口明确返回的选中文字。`Name`、`Value` 和整篇文档均不作为选区。
3. 读取器按实际目标记录失败状态。其他控件的空选区不覆盖目标的“接口不支持”。只有原生窗口代理、正文树尚未就绪时，保留有上限的结构事件等待；成功路径不等待。
4. 目标缺少只读选区接口时，复核来源后进入标准复制。手动快捷键明确请求取词时，也允许在焦点接口只返回空选区的情况下询问应用的复制命令；自动触发仍尊重目标的明确空选区。
5. Host 等待选择组合键释放，使用 Windows/Qt 标准 `Ctrl+Insert`。输入带专用标记，不触发自己的监听；不向终端发送可能表示中断的 `Ctrl+C`，也不依赖终端名单。
6. 保存原剪贴板，等待内容变化后读取，更新等待上限为 500 ms；收到内容即可继续。按所有者和用户复制/剪切版本检查并发变化，在同一剪贴板锁内恢复原内容。带文件载荷的结果不当作选中文字。取消和读取超时不会发布工具栏成功结果。

恢复剪贴板所需的短命窗口在发送复制键前创建。无法保存原格式、恢复失败、按键注入失败等仍返回真实错误。读取进程保留单实例队列、总超时和 Job Object 子进程回收；剪贴板清理不随读取取消而中断。没有新增常驻进程或后台持续轮询。

键盘和手动取词优先把工具栏放在选区旁；复制回退没有选区位置时使用当前鼠标位置，不再落到屏幕原点。

## WinOne 自身的标准复制

MyGo 0.9.0 的基础输入框与可选段落原先只接受 `Ctrl+C`。在共享输入派发中把 `Ctrl+Insert` 交给原复制命令，保持输入框、跨段选区、富文本复制和密码保护一致。原始按键观察、自定义输入回调和其他快捷键不变，不为某个页面分别补处理。

版本仍为核对到的最新正式版 0.9.0，来源提交及许可未变。改编输入和新增测试登记在 `third_party/mygo-winone/source.json`；构建从锁定模块生成仓库内副本，不修改系统 Go 模块缓存。
