# 截图全量原生迁移

用户已选择截图全量原生化，要求复用社区真实实现，其他模块暂时不动。目标是完整移除截图运行链对 .NET 的依赖，保留 WinOne 的设置、AI、模型、程序管理和其他模块。

采用 Tools3000 v1.4.11 固定源码作为原生截图基础，具体来源在 `third_party/tools3000/source.json`。不以仿写画布、占位按钮或调用上游独立应用代替模块接入。现用 RapidOCRLite、OCR 模型和 Rust 录屏核心继续作为已有功能来源。

默认构建和固定安装器已接入新原生目标。下表记录每项能力的实现与实际验证边界，未测硬件场景不写为通过。

## 已取得的运行证据

- 本地 OCR：原算法编译为 NativeAOT；25 组生成图片的文字与字符坐标和旧包逐值一致。另有 56 阅读顺序、14 自然段、150 布局保留回归。模型摘要未变；PE 与进程加载检查没有外部 CoreCLR/JIT。
- 社区真实窗口：选区、单次 Esc、序号连续输入/重新编辑/移动删除/撤销、保存 PNG、草稿崩溃重开、工具栏取消保存恢复默认通过。Host 保存会回调截图进程更新设置，已覆盖此真实通信关系。
- 输出保护：另存为系统对话框取消、保存目录冲突均保留截图；活动截图冻结输出设置，下一次采用新值；错误设置不替换上次有效配置。
- 截图翻译：真实原生 OCR、社区段落合成与本地 Host 翻译夹具完成全流程；Tab、标注修改失效、取消、关闭选项后还原通过。翻译供应商未联网调用。
- 贴图：社区窗口创建关闭、重新标注及确认回写、原位翻译、Tab 对照与关闭选项还原通过。
- 滚动：只有测试程序注入生成页面，复用社区采集循环、重叠分析和真实拼接；原宽保留、长图编辑、右键/双击不退出、直接滚轮缩放、重拍取消恢复原长图通过。
- 生命周期：并发重复请求复用同一任务；连续取消/重新开始通过。取消记录先持久化，原图编码与清理后台完成。文件选择子进程随拥有它的截图进程退出，未完成草稿仍能恢复。
- 界面：实际 Direct2D 帧回读并目视。800 像素英文深色、150% 控件缩放及 640 像素中文浅色、200% 控件缩放下，主工具栏换行且按钮不越界/重叠；这不等于真实显示器 DPI 切换验证。
- 录屏：保留原 Rust DLL，C++ 真实 ABI、初始状态/非法配置/生命周期保护通过；原编码探针实际生成并读回 MP4/GIF，均保留 6000ms 和 3 个变动帧。原生 GIF 选项与系统保存目的地取消通过。
- 构建：正式截图构建脚本已跑通；一次候选扫描为 32 个 x64 原生 PE、完整动态依赖、17 个原文许可记录。此数字不是最终安装包结果。

## 尚需收敛的验证

旧草稿保留填色/边框、虚线、阴影、箭头头向与多点路径、文字内容和视觉折行，但由新的社区引擎重新绘制；未宣称与旧 ShareX 抗锯齿/排版逐像素相同。真实屏幕捕获、多显示器/DPI/HDR、屏幕阅读器及联网供应商未在本次隔离桌面测试中覆盖。其他模块逐文件保留基线，Host 因 OCR 程序入口变更重建，最终产物记录混合来源。

录屏控制完整测试单独复制未改动的 Rust ABI、会话、时间轴和编码器源码，只替换采集输入为 `tests/capture-native/recording_source.rs` 的生成帧。测试DLL有明确文件名和导出标记，生产包校验拒绝此标记；生产构建仍使用原 windows-capture 采集及既有录屏DLL。真实WGC/控制栏排除未因此视为通过。

现用 MyGo 通过 `capture.unified`、`capture.activate`、`draft.get`、`draft.resume` 进入原生界面。旧 React 浏览器画布的 `draft.begin/update` 和 `selection.commit` 等消息没有现用产品调用；新进程明确拒绝未知消息，不以占位应答承诺执行。

运行证据、安装器解包校验、来源和旧版备份保存在 `dist/reports/native-capture-20261125/`。生产入口是 `build/build-capture.ps1` / `build/build.ps1`；私有桌面回归使用 `build/test-capture-native-cpp.ps1`。
