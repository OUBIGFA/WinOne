# AI服务：同一供应商的多个密钥

状态：2026-10-07，已完成实现与本地验收，日常试用版和已安装版均已更新。实际通过范围及正式版未完成项见 [开发状态](development.md)。

## 界面与默认行为

自定义供应商的 API 密钥区域提供一个“+”图标。每个密钥独立一行，使用密码输入框，可启用、停用和删除。沿用现有设置组件、图标、保存和未保存保护，不增加新的设置页或标签。

存在多个密钥时显示调用策略：默认轮询，也可按列表顺序使用。提供“失败时切换密钥”、最大尝试次数和失败冷却时间。默认开启切换、每次最多尝试 3 个不同密钥、冷却 60 秒；尝试次数不会超过本次可用密钥数。备用密钥被使用后会消耗其轮询轮次。只剩一个启用密钥时保留原来的即时手动重试；多个密钥都在冷却时明确报告原因，不改用其他供应商。

截图 OCR、翻译、划词和后续对话通过同一 AI 服务调用策略执行。模型选择仍属于供应商，密钥不会变成模型列表中的重复供应商。模型列表获取也使用该供应商的可用密钥。

## 共享服务边界

每个密钥有稳定 ID 和启用状态；公共配置只包含元数据。明文只通过写入请求提交，逐项使用现有 DPAPI 加密并原子保存；读取、日志、错误和跨设备偏好不返回明文。原单密钥自动呈现为首个密钥，保留其现有密文，无需重新填写。新增元数据和密钥集合必须保留旧配置投影及原子保存、revision 冲突检查。

WinOne Host 保管跨请求轮询位置和失败冷却时间，按需检查时间戳，不添加常驻轮询。magpie 继续执行协议适配。现有 AI Worker 每次调用后退出，不能将跨请求轮询计数只放在 Worker 内，否则每次都会从第一个密钥开始。

每次请求固定供应商、模型和候选密钥快照。候选密钥每次最多尝试一次。只在尚未产生正文或思考增量时，对认证、限流或暂时服务错误尝试其他密钥；无效请求、用户取消及已开始输出的流不自动重试。失败记录只能影响对应版本的密钥，编辑密钥后不能继承旧密钥的冷却状态。网络调用不持有配置锁。

## 当前与后两步

1. 存储和调度：实现旧密钥迁移、多密钥加密保存、删除/停用、并发安全轮询、顺序尝试及冷却；错误码采用结构化信息，不匹配供应商原始错误正文。
2. 接入和界面：在生成、翻译与模型发现调用中接入统一策略；增加密钥行与策略选项，完善双语及键盘操作。账号登录的现有隔离保持原样。
3. 验证与更新：回环供应商核验授权头顺序、并发、401/429/5xx 换钥、冷却恢复、已输出不重试及取消；核验无明文泄漏、旧配置/冲突/删除，完成界面和实际结果窗流程、构建后更新日常版。
