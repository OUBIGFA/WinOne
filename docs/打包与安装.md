# 打包与安装

当前提供本地免安装测试包。每用户安装器已通过隔离安装、卸载与中断恢复测试；完整更新、签名和干净机器验收尚未完成。

## 生成测试包

先完成同一版本的完整构建，再打包：

```powershell
./build/build.ps1 -OutputDirectory dist/build
./build/package.ps1 -BundleDirectory dist/build
```

Go 不在 PATH 时，两条命令都可传入 `-GoExe`。完整构建通过后，将版本和文件哈希写入 `build-info.json`；打包读取此记录，拒绝改标版本或构建后变动的文件。没有版本记录的旧构建需重新构建。

需要检查三个引擎及真实 WebView2 的启动与退出时，为构建添加 `-RunStartupProbes`。检查使用隔离配置，不执行截图、置顶或登录程序；普通构建不额外启用这项原生检查。

输出目录默认为 `dist/packages/`，已有同名产物不会覆盖：

- `WinOne-<版本>-windows-x64.zip`：运行文件、许可证、说明与文件清单。
- `.zip.sha256`：压缩包校验值。
- `.zip.manifest.json`：逐文件大小与 SHA-256，供安装器复用。

解压后运行 `WinOne.exe`，需要系统已安装 WebView2 Runtime。设置仍保存在 `%LOCALAPPDATA%\WinOne`，不会自动改为压缩包所在目录。

## 内容与校验

只收录三个基础模块的运行文件和许可证。调试符号不入包；发现配置文件、日志或其他未登记文件时拒绝打包。文件路径、重复条目、文件大小和哈希均检查，生成后重新读取校验。

当前格式为 `schemaVersion: 1`，目标平台为 `windows-x64`。单文件上限 256 MiB，总展开大小上限 2 GiB，清单上限 1 MiB，最多 8192 个归档条目。SHA-256 用于检查内容一致性，不能验证发布者身份。

```powershell
go run ./build/package --verify dist/packages/WinOne-0.1.0-alpha.1-windows-x64.zip
```

本次测试包包含 629 个文件，约 95.6 MiB。解压后通过模块关闭、维护后重启及 Host 程序类型检查；不代表干净机器安装已经通过。

## 准备安装器文件

安装器编译还会导出同版本的 `*-uninstall.exe`、两份 `.sha256` 和 `*-setup.exe.artifacts.json`。记录包含版本、平台、测试包标识、包内清单 SHA-256，以及安装器和卸载程序的文件名、大小与 SHA-256，供后续升级准备使用。已有输出不会覆盖，失败的 `.partial` 保留供检查。

导出使用 NSIS 官方 [`!uninstfinalize`](https://nsis.sourceforge.io/Docs/Chapter5.html#uninstfinalize)，取得安装器内嵌的同一份卸载程序，不需要先安装产品。导出阶段只复制和校验，不执行卸载程序。`build/test-installer.ps1 -ExportedUninstaller <导出文件>` 会先核对它与安装后文件一致，再使用导出文件完成隔离卸载测试。

使用导出文件前，可运行 `go run ./build/package --verify <目标包.zip> --verify-installer-artifacts <安装产物记录.json>`。命令核对版本、平台、包清单和两个程序文件，拒绝越界名称、大小超限及内容变动；测试产物必须显式添加 `--allow-test-installer-artifacts`。这是内容一致性检查，发布者校验沿用发布流程。

安装器源码为 `build/windows/installer.nsi`，统一编译入口：

```powershell
./build/build-installer.ps1 -Package dist/packages/WinOne-0.1.0-alpha.1-windows-x64.zip -NsisExe <makensis.exe路径>
```

输出到 `dist/installers/`，包含安装程序和 SHA-256。此阶段仅支持首次安装到空目录，拒绝覆盖已注册的安装；界面含许可、安装位置、进度和完成页，支持中英双语。检测 Windows 11 x64 与 WebView2，普通安装不提升权限。卸载入口先执行资源还原，再移除清单文件，保留配置和额外文件。

界面使用系统自带的 Segoe UI / Microsoft YaHei UI；详细文件列表默认收起，可按需展开。

当前编译产物仅供内部验收，不能作为正式安装器交付。隔离目录下的真实安装/卸载、注册表、快捷方式和文件保留已通过。首次安装捕获到失败时，在维护锁有效的前提下清理本次文件和注册信息；清理失败返回退出码 2 并保留现场。配置不参与清理。进程崩溃/断电后的恢复、部分卸载恢复、升级回滚、可视界面和干净机器测试仍未完成。

需要复现真实往返测试时，编译传入全新的、Git 已忽略的 `-TestDirectory`；再运行 `build/test-installer.ps1 -ContextFile <TestDirectory>/context.json -RunSystemIntegration`。测试版仅替换配置、快捷方式和独立注册表目标，实际文件安装与卸载流程不变。测试核对全部文件 SHA-256、注册位置和快捷方式目标，然后确认卸载保留配置及额外文件；结果保存在测试目录的 `result.json`。

加 `-TestRollback` 可在正常往返前验证文件写入完成后、注册完成后两处故障。故障开关只编译进 `-TestDirectory` 生成的测试版，分别用退出码 21、22 确认抵达预期位置；正式版不接受故障注入。

安装和卸载开始修改文件前创建 `.winone-pending` 标记并刷新句柄；完成或完整清理后才删除。界面与 Host 在安装锁内检查标记，存在任何同名对象或检查失败时拒绝启动，维护入口仍可进入。该标记用于阻止残缺副本运行，不代表已实现断电恢复或自动修复；旧版程序也不会识别它。

中断的首次安装可用原安装包执行 `/REPAIR /D=<原安装目录>`。交互模式发现已注册的未完成安装，或在目录页选中匹配目录时，会询问是否修复；拒绝即退出。静默模式不自动选择修复。只接受目录、产品、版本、操作类型和清单哈希全部匹配的恢复记录；已完成安装和中断卸载不走此入口。修复补齐清单内文件、注册信息与快捷方式，保留配置和额外文件；失败保留未完成标记及记录，成功后清除。

`build/test-installer.ps1` 的 `-TestRepair` 会中断测试安装进程，验证残缺副本拒绝启动、错误清单哈希被拒绝、修复失败保留现场，再完成修复和卸载。测试安装包以 `-test-setup.exe` 命名，采用快速压缩；生产包仍使用 LZMA。

卸载已还原资源并写入匹配记录、但文件清理中断时，可用原安装包执行 `/FINISHUNINSTALL /D=<原安装目录>`。该入口从安装包提取维护程序，不依赖目录内剩余的 Host/WinTray，且不要求 WebView2。记录不匹配、与其他已注册安装冲突或仍有运行实例时拒绝继续；完成后移除剩余清单文件、注册信息和快捷方式，保留配置及额外文件。它不能替代恢复记录写入前失败时的资源还原。

交互模式打开原包后，若已注册目录或目录页选中的位置有匹配的卸载恢复记录，会询问是否继续卸载，拒绝即退出。安装修复与继续卸载分别确认，不自动切换；静默模式仍需显式参数。WebView2 检查在选择操作后执行，继续卸载不依赖它。

`-TestUninstallRecovery` 会在程序文件移除后终止卸载，再用原包继续；还会验证错误哈希被拒绝，以及注册信息移除后再次终止仍可继续。注册项已不存在与查询失败分别处理，权限错误不会被当作“已清理”。

```powershell
./build/prepare-installer.ps1 -Package dist/packages/WinOne-0.1.0-alpha.1-windows-x64.zip -OutputDirectory _temp/installer-preparation
```

输出目录必须尚不存在且已被 Git 忽略。脚本校验压缩包后生成 `payload/` 和 `files.nsh`；Go 不在 PATH 时传入 `-GoExe`。NSIS 3.13 的下载来源及发布方 SHA-256 记录在 `third_party/sources.json`。

文件宏逐项安装和移除清单内文件，保留额外文件及非空目录。它们不处理运行中的模块、登录任务和配置恢复，不能单独作为安装器发布。

三个文件宏均要求传入守护函数名和失败标签，例如 `!insertmacro WinOneInstallFiles WinOneCheckGuard failed`，卸载使用 `un.WinOneCheckGuard`。每次目录创建、文件写入和删除前均检查守护进程；写入或删除失败立即跳转失败标签，结束时再次检查。清理目录只移除空目录，保留额外内容。调用方必须将失败显示为失败，并保留重试所需文件；这些宏不提供整包回滚。

删除前先检查完整文件清单的删除权限与共享占用；只读文件或被替换成目录/重解析点的文件会阻止删除。检查全部通过后才删除第一项，避免遇到清单后部既有占用时先删掉程序。预检查不持续持有每个文件的句柄，不能保证后续外部变化或中断时仍可回滚；每次实际删除仍检查错误。

预检查也核对安装根目录和清单中各级目录，拒绝目录链接、目录被替换为文件及无法确认的属性错误，防止沿目录链接删除外部文件。真实 junction 用例已验证外部文件和安装文件均保持原样；这不等同于消除检查后再被替换的竞态。

首次安装在获取维护锁前后检查目标目录，仅接受不存在或已确认为空的目录；文件目标、已有内容和枚举权限错误均拒绝。对应原生校验与 ACL 用例见 `TestNSISDirectoryValidation`。

## 安装与维护验收顺序

1. **维护协调**：阻止新操作，检查配置保存与截图编辑，释放快捷键，关闭截图与置顶，恢复 WinTray 管理的资源。任一步失败，停止删除并保留恢复资料；WinOne 自身登录任务另行处理。
2. **安装外壳**：每用户安装，检测 Windows 11 x64 和 WebView2，提供中英双语。维护成功后才替换或移除文件；卸载默认保留配置，额外文件不得递归删除。
3. **升级与回滚**：校验候选包，保留旧版本，验证新版本启动；失败返回旧版本。之后验证干净机器、离线安装、用户取消与文件占用场景，再进入签名及发布验收。

当前 Host 的普通退出不等于维护准备完成；完整安装器和升级入口尚未提供。

WinTray Worker 已提供 `uninstall.prepare`：按现有异步任务协议返回任务 ID，通过 `jobs.get` 获取结果。它先还原托管资源，再删除 WinOne 登录任务；失败可重试，配置和历史保留。普通 `deactivate` 保留登录任务。未运行的 Worker 由恢复模式启动，不执行登录程序。

Host 提供 `WinOne.Host.exe --prepare-uninstall`，要求先退出 WinOne 及其模块。命令保留 Host 管道占用，检查同名产品进程，调用 WinTray 恢复流程并等待退出；成功返回 0，失败返回非 0，不删除程序和配置。`--data-dir` 可指定隔离测试配置，与 `--autorun`、`--headless` 不能同时使用。进程检查参考 [Microsoft Toolhelp 示例](https://learn.microsoft.com/en-us/windows/win32/toolhelp/taking-a-snapshot-and-viewing-processes)，保守阻止其他副本和会话仍在运行的情形。

界面与 Host 在配置目录的 `maintenance.lock` 第 0 字节持有共享锁；卸载准备命令持有独占锁，锁冲突立即返回错误。锁文件不删除、不截断，进程退出后由 Windows 释放句柄。依据：[Microsoft LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex)。

此外，界面与 Host 按实际安装目录持有安装锁，切换配置目录不能绕过。目录通过 Windows 句柄解析最终路径，再以路径哈希定位 `%LOCALAPPDATA%\WinOne\installation-locks` 中的锁文件；安装锁先于配置锁获取，任一失败即释放已取得的锁。依据：[Microsoft GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)。

该命令结束后不再持有管道和锁。安装器仍必须在文件替换/删除期间持续阻止重新启动，并检查文件占用和每项删除结果；不能将一次准备成功视为后续操作一定安全。安装锁按当前用户隔离，其他用户会话及不遵守此锁的旧版本仍需进程和文件占用检查。

## 安装器守护接口

安装器可把 `WinOne.Host.exe` 复制到临时目录，以以下参数启动：

```text
WinOne.Maintenance.exe --guard-installation <安装目录> --installer-pid <安装器PID> --installer-ready <就绪事件名> [--prepare-uninstall]
```

安装目录必须已存在；维护程序必须在其目录树之外。安装器先创建未触发的 Windows 事件，启动维护程序后等待就绪，同时监测维护进程是否退出。维护程序持有安装锁、配置锁和 Host 管道；只有检查通过、所需还原完成才触发事件，随后等待指定安装器进程退出。

`--prepare-uninstall` 从目标目录运行 WinTray 恢复流程；省略时只执行占用检查，供首次安装及后续升级流程使用。`--data-dir`、`--pipe` 可用于隔离测试。安装器在文件操作全程必须监测维护进程，若提前退出则停止；守护接口尚未接入最终 NSIS 界面及文件事务。

`build/windows/maintenance.nsh` 提供 NSIS 守护函数：`WinOneStartGuard` 创建就绪事件和维护进程，同时等待就绪或进程退出；`WinOneCheckGuard` 检查维护进程是否仍在运行。调用方检查错误标志，每次文件操作前和最后一次操作后均需检查，失败立即停止。`WinOneCloseGuardHandle` 仅在结束时关闭安装器持有的进程句柄，不终止维护进程。

通过 `WinOneGuardFunctions` 宏的空前缀及 `un.` 前缀分别生成安装和卸载函数。当前使用 NSIS x86 Unicode 结构布局。验证命令：设置 `WINONE_NSIS_EXE` 和 `WINONE_HOST_EXE` 后，运行 `go test ./tests/integration -run '^TestNSISGuardProtocol$' -count=1`。该测试实际编译并运行 NSIS，覆盖就绪、失败及测试所属维护进程被终止的情形，不修改注册表和用户配置。

## 接下来三步

使用备份前可执行 `--verify <旧ZIP> --verify-backup <备份目录>`，复核载荷、完成记录和卸载程序。旧备份若未记录卸载程序是否存在，不作为完整安装状态备份接受；校验仍不等于发布者签名或已经完成回滚。

`--verify <旧ZIP> --installed <目录> --backup-registration <备份目录>` 保存当前用户 64 位卸载注册项，默认读取 WinOne 的注册键。记录绑定旧包清单哈希，保留值类型和原始字节；键不存在单独记录，读取错误不当作不存在。存在的注册项必须指向该安装目录，拒绝子键和超限数据。测试可用 `--registration-key` 指定隔离键；真实临时键测试需设置 `WINONE_REGISTRY_LIVE_TEST=1`。此阶段只备份，不恢复注册表。

`--verify <旧ZIP> --backup-shortcut <备份目录> --shortcut-file <原.lnk>` 保存快捷方式的原始字节、存在状态和哈希，绑定旧包清单。读取不调用 Shell 解析或执行目标，格式头参考 [Microsoft MS-SHLLINK](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-shllink/)；头部校验不证明目标可信或可运行。拒绝超限文件和目录链接，不覆盖已有快照。这是本机回滚资料，不属于跨设备配置导出。

快捷方式恢复接口要求原快照、升级写入后的预期快照及显式目标路径。当前内容已变动时拒绝覆盖，已恢复时允许重复调用；原先不存在时只移除匹配升级写入状态的文件。恢复后重新读取核对。调用方仍须持有维护锁；内容比较不是对任意外部写入者的原子锁定。该接口尚未接入完整升级执行器。

注册表恢复同样要求原快照、预期当前快照和明确的键路径。先校验目录归属、类型、大小与重复值名，再核对当前内容；恢复原始类型/字节，移除升级新增的值，并复核结果。原先无注册项时仅删除匹配预期状态的键，显式使用 64 位视图。多值写入不是原子事务，中途失败会返回错误，仍需升级日志记录进度并驱动恢复。

升级日志已提供准备、应用、验证、提交、恢复和已回滚阶段，覆盖每个载荷文件以及清单、卸载程序、注册表、快捷方式。写入和恢复意图须先落盘，完成后再确认；存在未完成步骤时不能提交或结束回滚。日志带版本与哈希约束、修订检查和大小限制，写入失败不推进内存状态。它记录调用方报告的进度，不代替文件验证或维护锁；尚未接入执行器。

日志已接入单文件执行接口：应用/恢复前核对旧、新哈希，先写意图，再通过临时文件替换或删除，复核后确认完成。已完成字节与未确认日志可在重开后继续；发现第三种内容时停止并保留现场。接口要求串行调度、维护锁、已验证的来源和未完成标记；不会自行清除标记或提交整次升级。元数据协调、全包验证和启动确认仍由完整执行器负责。

版本清单遵循相同日志流程，但必须等待全部载荷文件应用或恢复完成。`VerifyUpgradePayload` 可在保留未完成标记的情况下核对完整包内容，不将目录报告为已提交安装；普通 `VerifyInstalled` 仍拒绝未完成标记。清单写入或恢复后、完成日志写入前中断，可依据绑定哈希继续确认。

快捷方式现通过日志执行应用/恢复：先绑定原、新快照指纹，再记录意图；完成后读取核对。无变化时明确记为 unchanged。已记录意图的中断可识别写入结果，未绑定快照的旧意图不会直接重放，更换快照或出现外部内容会停止。

注册表也接入相同阶段控制。记录写入意图后，可识别仅由原、新快照已知值组成的部分结果，继续应用或恢复；新键尚未写入 InstallLocation 的情形也可处理。没有意图时不接受部分状态，外部新增值、第三种内容和更换快照均拒绝。调用方仍须串行执行并持有维护锁，多值操作不宣称具备系统级原子性。

卸载程序的应用/恢复也使用绑定描述与日志，核对旧、新文件的固定名称、大小和哈希；明确保留便携场景的缺席状态，不执行卸载程序本身。调用方必须提供与目标版本匹配、已验证的生成产物；文件内容校验不能替代新版卸载行为验收。

整体升级调度已串联以上步骤，校验包/备份/元数据、取得安装与配置维护锁、绑定本次标记和快照，再执行更新、校验与探测；失败转入日志驱动的回滚。支持部分应用/恢复后重开，拒绝活动运行租约、其他操作标记和过期日志。默认准备流程调用真实 WinTray 恢复并等待退出，保留 WinOne 登录任务；发现产品进程仍在运行则要求先退出。默认启动检查串联 Host、配置、Worker 和 WebView2，结束后重新核对原配置。完整文件包的便携切换与坏程序回滚已通过真实程序测试；对外更新入口尚未开放。

更新能力按以下顺序继续推进：

完整真实程序回归：设置 `WINONE_UPGRADE_OLD_BUNDLE`、`WINONE_UPGRADE_NEW_BUNDLE` 为两个完整构建目录，`WINONE_UPGRADE_LICENSE` 为许可证文件，再运行 `go test ./internal/distribution -run '^TestNativeUpgradeExecutesVerifiedBinaries$' -count=1 -v -timeout 300s`。用例在临时副本中生成专用测试版本，覆盖正常切换和损坏界面程序后的回滚；不修改源构建，不生成发布包。此用例为便携场景，安装注册和卸载仍需独立验收。

安装版本回归额外设置 `WINONE_NSIS_EXE`，运行 `go test ./internal/distribution -run '^TestNativeInstalledUpgradeThenUninstall$' -count=1 -v -timeout 600s`。用例使用真实安装器、卸载程序、隔离注册项和快捷方式，覆盖“升级成功后卸载”与“升级失败回滚后卸载”。两条路径已通过，配置和额外文件保留；不等同于签名发布或旧配置迁移完成。

2. 本地升级入口：串联真实准备与探测，核对新版卸载程序及配置兼容性。验收覆盖真实版本切换、探测失败回滚、中断恢复和升级后卸载。

Host 探测基础已实现：`--check-startup <随机标识>` 只输出启动报告并退出，拒绝附带运行参数；不读取用户配置、不启动模块或界面。`internal/startupprobe.Check` 从已验证的程序路径启动探测，核对进程身份与模块清单，限制输出和等待时间，并等待进程退出。真实回归通过环境变量 `WINONE_HOST_EXE` 指向已构建 Host 后运行 `go test ./internal/startupprobe -count=1`，使用隔离副本和配置。依据 [Go os/exec](https://pkg.go.dev/os/exec#CommandContext) 的取消和 `WaitDelay` 约定；超时仅终止本次创建的探测进程。它不代表普通 Host、Worker 或 WebView2 已完整启动，不能单独作为升级提交依据。

`internal/startupprobe.CheckWorkers` 检查三个内置引擎的真实启动及退出。调用方提供已验证的安装目录和安装目录外的诊断目录；每个 Worker 获得独立空配置，最长等待 20 秒。检查不加载真实用户配置，失败保留诊断数据。WinTray 必须完成异步初始化，不能仅以管道可连接判定成功；各 Worker 身份匹配后才发送退出请求。独立复测可设置 `WINONE_PROBE_BUNDLE` 为完整构建目录，再运行同一测试包。完整升级仍需配置兼容和 WebView2 检查，不能只以此提交。

`internal/startupprobe.CheckConfiguration` 将完整统一配置交给目标 Host 只读校验，使用正常加载的全局与三个模块规则，核对返回的配置哈希。目标进程通过 `--check-configuration <随机标识>` 从标准输入读取，最多 8 MiB，最长等待 15 秒；报告不包含配置内容。未完成事务必须先恢复，缺失模块或旧版散配置必须先完成迁移。此入口不转换配置、不启动功能，不代表配置迁移或升级提交已完成。

`internal/startupprobe.CheckDesktop` 在独立缓存中打开隐藏 WebView2，验证正式页面、样式、Logo、编辑器资源和 Wails 通信；最长等待 30 秒。页面读取隔离配置服务，不启动用户 Host 或 Worker。只有收到页面确认并正常退出后才通过。入口为 `--check-ui <随机标识> --probe-root <安装目录外的诊断目录>`；诊断目录须已存在，缓存由调用方管理。复测设置 `WINONE_DESKTOP_PROBE_EXE` 后运行 `go test ./internal/startupprobe -count=1`。依据已锁定 Wails v2.14.0 的 [窗口选项](https://github.com/wailsapp/wails/blob/v2.14.0/pkg/options/options.go) 与 [WebView2 缓存选项](https://github.com/wailsapp/wails/blob/v2.14.0/pkg/options/windows/windows.go)。该项不替代真实用户操作和升级后完整回归。

升级差异检查可通过 `go run ./build/package --upgrade-from <旧ZIP> --verify <新ZIP>` 生成 JSON 清单。两个包先完整校验，再按 [Semantic Versioning](https://semver.org/) 比较版本；仅接受更高版本，同版本修复仍使用恢复入口。清单记录新增、替换、删除、不变文件及前后哈希，保留大小写改名信息。

该命令不修改安装目录，不验证发布者身份，也不证明当前安装文件仍与旧包一致。切换前仍须核验实际安装、备份待替换内容，并验证失败恢复。

增加 `--installed <目录>` 可核对实际文件：单独配合 `--verify <旧ZIP>` 检查当前目录；配合 `--upgrade-from <旧ZIP> --verify <新ZIP>` 时，在输出升级计划前检查当前目录。未完成标记、清单差异、缺失/改动文件和目录链接均拒绝；清单外文件不读取、不修改。检查使用限定根目录的文件访问，但不会持续锁定所有文件，执行升级时仍需重新确认。

`--verify <旧ZIP> --installed <目录> --backup <新备份目录>` 会从当前目录复制已核验的包文件，检查每份副本并复核完整备份，最后写入 `backup-complete.json`。备份父目录须已存在，目标不能已存在或位于安装目录内；失败保留未完成输出，不覆盖旧备份。备份同时保存存在的 `Uninstall.exe` 及其大小/哈希；没有卸载程序时明确记录其缺席。用户配置、额外文件和注册信息不在此备份范围。真正升级时还需持有维护锁，并单独保存注册表及快捷方式状态。
