## 构建与安装器交付顺序

复用固定工具链，不重新下载已有资源。以下输出目录是建议新目录；使用前确认不存在同名产物。

```powershell
. ./build/use-local-resources.ps1
./build/build.ps1 @WinOneBuildParameters -SkipInstall -RunStartupProbes -OutputDirectory _temp/20261020-ui-ai-delivery/build
./build/package.ps1 -GoExe $WinOneBuildParameters.GoExe -BundleDirectory _temp/20261020-ui-ai-delivery/build -OutputDirectory _temp/20261020-ui-ai-delivery/package
```

1. 以新 ZIP 调用 `build/build-installer.ps1`，传入 `$WinOneNsisExe`、`-GoExe`、新 `-OutputDirectory` 和新 `-TestDirectory`。`-Package` 必须传 ZIP，不是构建目录。
2. 使用脚本生成的 `context.json` 运行 `build/test-installer.ps1 -RunSystemIntegration -TestRollback -TestRepair -TestOverwrite -TestHistoricalJournal -TestUninstallRecovery`；传入导出的卸载器并保留配置／额外文件核查。上下文不能手写，路径参数按脚本要求使用。
3. 对最终生产包运行 `settings-native-check.mjs` 时清空 `WINONE_SETTINGS_DEV` 和 `WINONE_SETTINGS_ASSETS`；重新核对深色页面、真实路由／插件与正常退出。当前实窗只能证明最新 UI 在原生 Host 中可运行。
4. 用同一 ZIP 生成不带 `-TestDirectory` 的正式安装器；按现有流程扫描安装器、卸载器、ZIP 与载荷。不得将测试安装器当成正式安装器。
5. 验证后备份 `dist/release` 三件套到任务 `_temp`，更新 `WinOne-setup.exe`、SHA-256 和 `release-info.json`。不启动正式安装器，不改用户真实安装。
