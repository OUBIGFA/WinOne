# 程序管理计划任务权限修复

更新：2026-11-07。范围为 WinOne 程序管理的任务更新、原生任务接管/恢复，以及启动失败后的重试。

## 原因

只读检查确认，报错的四个 `WinOneWinTrayApp-*` 任务均为 `LeastPrivilege`，但安全描述符的所有者为管理员组，当前用户只有读取权限。任务操作仍指向此前的 WinOne 路径，当前 Worker 使用的路径不同，因此启动同步需要更新任务。

任务的运行级别决定目标程序如何启动，不决定谁可以修改任务。原实现仅根据运行级别选择管理员帮助进程；普通任务更新失败直接返回，没有处理管理员创建的普通任务。迁移流程随后尝试回滚删除，但同样没有权限，于是同时出现 `/Create`、需要授权和 `/Delete` 三类错误。

另一个缺口在 Worker：后台初始化失败没有影响“配置相同则跳过”的判断。用户重试恢复时，可能未执行系统修改就被报告为成功。

## 修改

- 自建替代任务、原生任务的接管和还原共用注册入口。普通权限注册失败后，用户主动保存或恢复时通过现有管理员帮助进程重试一次；后台同步仅返回待确认错误。
- 注册过程保留目标任务原来的运行级别，不将普通程序改为管理员运行。已是管理员的进程直接返回真实失败，避免重复提权。
- 授权取消或帮助进程失败会返回错误，并保留首次注册失败的原因。已有任务匹配时跳过注册，避免重复授权。
- Worker 只有成功应用过系统设置，才允许跳过内容相同的配置。初始化失败会显示现有的“恢复上次设置”操作；恢复必须实际重试，失败时保留错误，成功后才清除。
- 独立程序管理构建入口补齐原生图标生成，支持没有旧构建缓存的源码目录。

## 验证

新增回归先在旧实现上失败，证明能捕获普通任务缺少提权重试、模拟管理员状态未被统一使用，以及恢复误报成功的问题。覆盖配置启动、Run 启动项迁移、原生任务写入、后台不弹确认、用户确认、取消确认、管理员进程失败及重复同步。

独立源码中的完整程序管理测试、vet、x86/x64 原生桥 ABI、生产 Worker/恢复程序构建及构建后 Worker 联动检查通过。权限与恢复测试的外部系统边界使用受控返回值，不代表真实任务已被修改。两个新组件的 Defender 非修复扫描通过。

启动优化任务随后在主工作区完成合并版本的同一套检查，日志为 `_temp/startup-20261107-9f4b/wintray-final-current.log`，候选包在该任务的 `integrated/`。根据最新接管安排，本任务停止独立打包、提交、推送及更新正式安装器，由启动优化任务统一交付。交接文件：`_temp/20261107-wintray-task-permissions/handoff.md`。

独立打包准备曾因归档源码缺少已生成资源、换行影响固定摘要和缺少 MathJax 本地依赖而中断，没有形成安装器验收结论。尝试重建旧网页界面另暴露既有 TypeScript 接口错误；该界面不用于当前 MyGo 原生包，未将其列为本次已修复项。完整记录仍保留在本任务临时目录，统一交付使用主工作区的构建与验证结果。

## 使用

用户自行安装修复包后，在程序管理页点击“恢复上次设置”。Windows 出现管理员确认时选择“是”。多个受保护任务可能分别请求确认。恢复成功后，后续未改变的任务不再重复确认。

没有自动修改本机真实安装、真实配置或上述计划任务。自动回归中的权限结果通过受控系统边界返回；不将这些回归冒称为用户真实任务已恢复。
