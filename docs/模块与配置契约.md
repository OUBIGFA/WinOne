# 模块与配置契约

状态：**目标契约，尚未完整实现。** 实施顺序以架构路线图为准；下列名称用于约定职责，不代表已有可调用 API。

## 已接入的统一托盘契约

- 产品设置、模块设置、托盘入口均由 WinOne 呈现。Worker 不保留独立产品界面。旧 WinTray 配置兼容不增加独立导入入口。
- `wintray.icons` 返回原生收纳图标及托管程序。托管程序额外标记 `hosted: true`，使用只在本次托管期间有效的条目 ID；`image` 为 PNG。
- `wintray.icon.activate` 使用条目 `id`。原生图标沿用 `right` 打开原程序菜单；托管程序使用 `action`：`open`、`hide`、`release`、`quit`，菜单由 WinOne 绘制。
- Worker 验证条目仍存在且进程创建时间一致。动作只表示请求已发出，退出或取消托管后的条目移除仍由实际进程、窗口恢复结果确认。
- 禁用或退出必须恢复托管窗口及原生图标。UI 查询不启动空闲 Worker；模块在存在托管条目时保留必要后台资源。

## 1. 模块清单

基础模块与扩展采用同一种清单。保留现有稳定 ID：`capture`、`always-on-top`、`wintray`；扩展使用发布者命名空间，避免冲突。

清单需要包含：

| 字段 | 用途 |
| --- | --- |
| manifestVersion、id、version | 清单与模块身份 |
| distribution | bundled 或 optional |
| hostRange、protocolVersion | 安装前判断兼容性 |
| platforms、最低系统要求 | 阻止在不受支持的系统上加载 |
| dependencies | 共享运行时和模块依赖，解析后形成锁定清单 |
| entrypoints | 包内相对路径的 Worker 与 UI 入口 |
| capabilities | 声明系统能力；Host 校验允许的调用，不接受任意 shell 命令 |
| activation | 按需、登录任务或配置驱动的常驻策略 |
| settingsSchemaVersion、schema | 配置校验、迁移和导入预览 |
| locales、designSystemRange | 双语资源和统一组件兼容范围 |
| files、signature | 文件大小/摘要及发布者签名信息 |

首轮仅支持经过项目审核的模块代码。能力声明和独立进程不能替代安全沙箱；不向未经审核的模块承诺安全执行任意代码。

截图操作界面及新增模块UI采用原生控件并复用WinOne的导航、表单、状态、主题和双语设计系统。置顶功能和程序管理保留现有界面及实现，不做原生化迁移。简单设置由共享原生UI宿主按声明式schema呈现；特殊工作流使用审核后的原生界面入口与共享控件库。新增模块不使用网页UI包，也不各自携带独立常驻UI宿主。保留的现有网页界面继续维护，不作为新增模块的目标技术模板。

接入前必须提交同负载原型与资源预算，明确共享运行时及加载/卸载边界；验收覆盖完整进程组、首次与再次调用、空闲、禁用和关闭后的回收。UI契约版本及包兼容检查须随原生迁移更新，不能把旧网页入口伪装为兼容的原生入口。现有配置schema、稳定模块ID及恢复协议保持独立于显示技术。

## 2. 分离三种状态

- **安装状态**：未安装、下载中、校验中、已安装、更新中、卸载中、失败。
- **用户意图**：启用或禁用，持久保存。
- **实际状态**：休眠、启动中、运行中、停止中、故障，来自引擎确认。

“已开启”不代表进程必须常驻；“关闭中”不代表已成功释放资源。故障不能伪装成关闭或安装完成。

建议的模块命令面：

| 类别 | 命令职责 |
| --- | --- |
| 发现 | describe、capabilities、health |
| 生命周期 | start、prepareStop、stop、recover |
| 配置 | validate、apply、restore |
| 功能 | 模块限定的 typed commands |
| 常驻 | blockers、活动任务、资源归属摘要 |
| 诊断 | 经脱敏的错误码与日志入口 |

耗时操作统一返回任务 ID、状态、进度、结果或错误。重试/取消需有确定行为；重复请求不能重复注册任务或执行程序。

## 3. 禁用和卸载的共同事务

1. Host 锁定模块变更，拒绝新动作；保留状态查询。
2. 解除快捷键注册，停止新的定时调度。
3. 引擎报告未完成工作与恢复要求。
4. 当前编辑交给用户完成或取消；不能通过杀进程达成“已关闭”。
5. 恢复本模块拥有的窗口、托盘与系统状态。
6. 等待进程退出，确认没有残留回调和资源。
7. 提交禁用状态；卸载才继续移除包文件。

失败后记录实际完成阶段，支持重试恢复。发现系统资源已被外部修改时保留冲突，不覆盖新值。卸载默认保留设置，删除配置是另一项明确操作。

共享运行时只能由包管理器维护。更新或删除时检查引用，不能让卸载一个扩展破坏基础模块。

## 4. 配置中心边界

原生截图内修改工具栏偏好继续复用 Host 的 `capture.settings.get`、带修订号的 `capture.settings.save` 及配置任务结果，不写 Worker 的独立偏好文件。后续接入顺序：传递并校验 Host 管道及父进程身份；实现异步保存与任务结果确认；开放自定义菜单并验证冲突、取消截图、再次截图和重启后的偏好。只有 Host 确认保存后才更新已保存状态，失败保留当前编辑选择并允许重试；写请求不得自动重发。

保存任务的生命周期不得依赖截图窗口存续。开放菜单前，需让 Worker 跟踪未结束的配置请求，防止关闭截图后提前退出，也不能阻塞 UI 线程等待 Host 回调；收到结果后只更新仍存续的界面。

可迁移偏好由 Host 配置中心统一提交和持久化。Worker 接收配置快照、执行应用或恢复，并返回结果；运行历史与系统资源归属账本仍由对应引擎单独维护。

现有 Worker 自行保存偏好的接口需要逐步迁移，不能同时保留两份可写配置作为真相来源。迁移前备份并验证旧格式，成功后原子登记版本。

禁用模块的配置仍可查看与编辑：先进行 schema 校验，不为读取设置启动引擎；启用时再验证本机能力和资源。需要系统变更的设置必须经配置事务协调，不能绕开模块状态直接调用旧 API。

一项事务包含：事务 ID、配置修订、变更模块、待应用快照、已完成步骤与补偿状态。导出只读取已提交快照；并发修改需要版本检查，不能把不同时间点的模块配置拼成假一致的档案。

当前事务存储 `internal/configuration` 将已提交文档与待应用文档放在同一个原子替换文件中。运行时应用前先保存准备状态，全部成功后才提交新修订；失败时重新应用完整旧文档，恢复失败则保留准备状态。重启不自动接受待应用文档。`Apply` 适配器必须幂等、等待 Worker 异步任务结束，并且不能因恢复配置而执行程序启动队列。Host 接线、模块分阶段恢复记录及旧配置迁移尚未完成。

Host 全局设置现已接入：`configuration.json` 的 `host` 命名空间保存主题和快捷键，修订号只由外层文档管理。旧 `settings.json` 仅在首次迁移时读取，保留为原始文件；新文件损坏时拒绝启动，不退回旧值。当前启动恢复仅处理尚未创建原生资源的 Host 偏好；接入模块命名空间前，必须扩展恢复器，不能沿用全局偏好的空运行时恢复。未知命名空间暂时拒绝，避免旧版 Host 忽略模块恢复要求。

置顶现通过 `ModuleAdapter` 接入：启动恢复重新生成已提交配置的 Worker 投影；运行中保存等待 `settings.reload` 完成，失败后恢复旧投影与运行状态。`settings.get/save` 可在模块关闭时使用，其他动作继续受模块开关限制。Worker 不写该投影；缺失或损坏不回退旧文件。截图和 WinTray 的适配器尚未接入，完整事务状态页面与人工恢复入口待完成。

## 5. 配置档案格式

使用版本化的 `.winone` 配置归档，首轮为可检查的 ZIP 容器：

```text
manifest.json          格式版本、创建版本、模块与设置版本、摘要
profile.json           主题、语言、模块开关、快捷键等偏好
modules/<id>.json      各模块可迁移配置
paths.json             路径占位与待映射说明，不含固定本机身份
```

不包含可执行文件、DLL、脚本文件、模块安装包、日志、截图、PID、HWND、缓存、凭据和系统恢复账本。程序启动参数由模块导出策略声明；可能敏感的内容须在导出预览中可识别和排除。

当前设置页导出默认排除启动参数，程序与保存目录只保留映射引用。`profile.json` 同时包含 `runAtLogon` 和 `startMinimized`，避免遗漏目前保存在 WinTray 中的登录偏好。导出读取配置中心的单个已提交文档，不查询 Worker；模块开关在文档读取前后核对修订，变化时要求重试。

文件摘要用于完整性检查，不表示档案可信。解析需限制总大小、文件数量、解压后大小、压缩比与路径；拒绝目录穿越、链接绕过、未知执行内容和不支持的格式版本。

当前编解码器初始限制：档案与解压内容总量不超过 8 MiB，单文件不超过 2 MiB，最多 256 项；压缩条目采用比例与固定余量限制。仅在内存读取允许的 JSON 文件，不向磁盘解包。模块 payload 的业务字段和敏感内容仍需由适配器校验与筛选。

当前基础模块导出适配器位于 `internal/profiles/builtin.go`，输入为已加载的设置对象；不读取文件、不启动 Worker。输出采用独立的可迁移 schema v1：截图使用 `outputDirectoryRef`，WinTray 程序使用 `programRef`，置顶排除项使用 `name` 或 `pathRef`。路径清单不保留源机器位置。WinTray 参数按程序 ID 显式选择，未选择项返回省略清单；不复制脚本内容。未知源字段丢弃，源配置版本不匹配则拒绝；导入业务校验与一致快照采集已接通；真实Host双目录回归验证了路径映射、缺失程序拒绝导入、重启与再次导出。不同设备/用户和系统文件对话框仍待验收。

配置迁移是数据转换，不能运行档案附带代码。旧模块设置版本由已安装的、可信的迁移实现转换；缺少转换器时保留原数据并明确提示。

## 6. 设备映射与导入

可迁移设置引用语义位置，如用户图片目录、程序条目 ID；本机映射负责解析实际路径。标准目录使用 Known Folders [S12]，不能仅把用户名做字符串替换。

导入预览需要说明：

- 将新增、修改、保留哪些设置。
- 哪些程序位置需要选择、哪些模块尚未安装。
- 哪些快捷键有冲突、哪些权限无法在本机满足。
- 哪些本机自启行为将改变，哪些字段不支持迁移。

用户可以按模块导入，也可以替换整个偏好档案。缺失模块的配置保留；缺失程序不执行，提供修复路径。应用失败恢复到上一个已提交版本，并保留可重试报告。

当前 `PrepareBuiltinImport` 已实现三个基础模块的数据预处理，输出配置补丁、缺失路径和带参数程序清单。路径必须来自接收设备的映射，不能使用档案中的提示自动绑定；任一路径未映射时不返回补丁。此结果不代表可以直接保存：提交层仍须检查本机文件、权限、修订号和资源状态，并合并本机元数据。该接口不写文件、不执行程序，也不代替 Worker 的最终配置校验。

“公司/家里”属于不同设备映射；配置档案可相同，窗口句柄、登录任务名称、权限令牌和资源归属不能相同。后续同步只交换已提交档案，不直接同步工作目录和恢复账本；冲突保留版本供选择。

## 7. 界面与语言契约

配置导入预览使用 `import.preview.start/read/release` 分块传输。后台仅保留一个不可变预览，最大 64 MiB，90 秒过期；每块最多 128 KiB，桌面端按连续偏移读取并校验总长度与 SHA-256。该上限用于覆盖已有档案数据序列化膨胀，不改变档案的 8 MiB 限制。

传输令牌只用于读取预览，不授权导入；实际应用仍复核源档案摘要和配置/模块修订。新预览会替换旧令牌，过期、乱序、串包或摘要错误均拒绝显示。旧单帧接口对大预览明确报错，避免截断或无响应。

模块必须提供统一设置入口、能力名称、错误码、快捷键动作和语言键。Host 的设计系统决定控件外观、导航、焦点与反馈；模块不得注入另一个产品的主界面。

基础模块在中文和英文下都必须完整可用。错误返回机器可判定的 code 与参数，用户文本由语言资源生成；原生系统原文放详情。

禁用模块必须通过所有入口生效：面板、首页快捷动作、全局快捷键、托盘菜单、协议调用、登录任务和后台定时器。隐藏按钮不是禁用实现。

## 8. 安装和更新契约

共享依赖使用包元数据 v4，模块与无 Worker 的运行时包分别声明种类。依赖精确绑定种类、ID、版本和签名清单摘要；Host 在安装、启动和回收时重新核对，不能只按名称选择最新版本。共享版本并存，使用者仍在登记或恢复事务中时不得删除；模块本身被另一模块锁定时也不能直接更新或卸载。格式、运行上下文及当前验收状态见 [共享依赖设计](共享依赖设计.md)。

清单、依赖与文件都通过校验后才允许激活版本。包管理器禁止解包时执行脚本；处理相对路径、重解析点和解压配额；按固定可信入口创建 Worker。

更新分为下载、准备、切换与确认，保留上一有效版本。当前有任务或恢复失败时暂缓更新，不能覆盖运行中的 DLL。签名、版本、有效期和兼容关系属于校验内容；设计参考 TUF 的攻击模型 [S11]。

模块设置和本机恢复数据与包版本分离。卸载旧包、回滚程序或更新引擎都不得顺带删除用户档案。

## 9. 每个新增模块必须交付

清单与依赖、统一 UI 路径、双语资源、配置 schema/迁移/导出策略、启停/恢复、快捷键声明（有实际需要时）、资源预算及测试、许可证与签名材料。

默认验证：关闭后无进程/快捷键/后台任务；安装失败不执行代码；卸载后资源可恢复；缺依赖和旧配置有明确处理；断网仍可使用已安装能力；资源增量满足预算。

[S11]、[S12] 的链接见 [统一体验与设计依据](统一体验与设计依据.md)。

## 10. 截图编辑契约

`edit.apply` 接收 `expectedId`、保存路径和 `document`。图像标识在整个编辑会话中固定，保存前必须核对；不会把旧标注应用到另一张截图。

- `document.width/height` 始终是原图尺寸；所有标注使用原图像素坐标，预览缩放不改变导出坐标。
- 版本 1 支持标注；版本 2 增加可选 `crop: {x,y,width,height}`，裁剪坐标为整数。带裁剪的版本 1 请求拒绝执行。
- 先按原图坐标合成标注，再裁剪到保留区域；未裁剪时维持原尺寸。原文件保持不变。
- 裁剪范围必须非空且位于原图内。最多 512 个标注、16384 个笔画点；文字最多 4096 个 UTF-16 代码单元。
- 撤销历史同时保存标注与裁剪，前端保留最近 100 步；撤销后新操作清除重做历史。

旧引擎不接受裁剪文档；调用方必须显示失败，不得退回未裁剪保存。输出成功后生成新的图像标识和预览。

`edit.preview` 接收同一 `expectedId/document`，不接收保存路径。它按导出规则渲染并返回 `id/sourceId/width/height`，不修改原图、最近截图记录或剪贴板。预览最长边 1600 像素。

编辑预览通过 `/capture-edit-preview/<id>.png` 读取，仅允许当前原图对应的最新编辑预览；旧标识或原图改变后拒绝读取。新预览发布后清理上一个文件，清理失败作为操作失败返回。界面修改文档后不得继续显示旧预览作为当前结果。

## 11. 截图编辑交接路线

按钮和全局快捷键使用同一草稿会话。默认区域截图已切换至统一入口，其他原生交互继续补齐。

1. 截图引擎保存一份原图、预览、开始时的设置和标注文档，返回草稿 ID。草稿与最近已保存截图分开；每次文档更新递增修订，拒绝旧修订覆盖。取消只删除当前草稿，保留此前截图。
2. 桌面按钮直接接收草稿；快捷键由 Host 将草稿 ID 交给 WinOne 窗口。窗口首次启动和已运行两种情况都需处理，重复交接不得覆盖正在编辑的内容。重新启动可恢复草稿文档。
3. 界面关闭前完成文档保存或明确放弃；完成时使用草稿设置执行保存、复制和贴图。失败保留草稿供重试。按钮、快捷键、取消、重启、模块禁用和文件写入失败均验收后，再替换默认入口。

草稿 ID 不接受文件路径；原图位置由引擎派生。活动草稿阻止新的截图覆盖它，但不要求截图 Worker 为草稿保持常驻。原生选区工具栏、滚动预览和贴图菜单继续按统一设计补齐。

当前引擎接口已实现，默认按钮和快捷键已接入统一入口：

| 方法 | 输入 | 结果 |
| --- | --- | --- |
| `capture.unified` | `mode` | 开启编辑偏好时返回 `draftId`，否则执行截图后任务 |
| `draft.begin` | 已保存截图的 `expectedId` | 创建另存为草稿，不重复自动复制或贴图 |
| `draft.get` | 可选 `expectedId` | `{draft}`，含设置快照、修订和文档；无草稿时为 null |
| `draft.update` | `expectedId/revision/document` | 异步确认 `draftId/revision`，不在任务缓存中保留整份文档 |
| `draft.cancel` | `expectedId/revision` | 清理当前草稿，不改此前截图 |
| `draft.complete` | `expectedId/revision`，可选 `path` | 按已保存文档和设置完成导出；需要选择路径时必须先提供路径 |
| `draft.copy` | `expectedId/revision` | 复制当前标注与裁剪结果，保留草稿，不额外保存文件 |
| `draft.pin` | `expectedId/revision` | 贴出当前结果，保留草稿，不替换最近已保存截图 |

草稿持久化内容最多 768 KiB，为 1 MiB 通信帧保留余量；通信响应使用紧凑 JSON，请求 ID 最多 128 字符。更新失败不推进修订。草稿原图和预览清理完成后才移除元数据，使取消失败可以重试。

`edit.preview` 同时支持当前已保存截图与活动草稿的 ID。预览资源读取也支持活动草稿，仍拒绝过期 ID、损坏元数据和越界路径。

窗口交接通道已建立：`--capture-draft <id>` 在首次启动与 Wails 第二实例回调中进入同一队列。队列在窗口进程内保留，最多 8 项；重复草稿合并，确认必须匹配队首请求 ID。草稿本身仍由引擎持久化。

前端通过 `CaptureLaunch/AcknowledgeCaptureLaunch` 读取与确认，`winone:capture-launch` 只负责通知；先订阅再读取，避免启动时漏掉事件。接收器串行处理，只有编辑视图明确接收后才确认；忙碌或卸载时保留请求。接收器已挂载到主界面的可恢复工作区。主窗口启动时只读检查草稿元数据，有未完成草稿才交给引擎加载；无草稿时不为检查而启动截图 Worker。已有截图的编辑已使用该工作区，默认区域截图已使用新选区工具栏，仍需多屏和真实快捷键全链路验收。

工作区自动保存已经提交到画布的标注，串行更新修订并合并等待中的修改。连接中断后仅在服务端文档与已知版本一致时恢复写入；不同文档按冲突处理。保存和放弃会等待在途写入。原生关闭请求转为编辑器确认，继续编辑会撤销待关闭状态。未应用的属性输入不属于已保存标注文档。

统一截图请求携带解析后的 language（zh-CN 或 en-US）。区域选区工具栏跟随主题，确认沿用截图后设置，编辑按钮可直接请求 WinOne 编辑器；取消和显示变化不保留选区。

窗口截图同样使用原生工具栏；目标列表按 Z 顺序采集，在截图前后复核，最多遍历 4096 个顶层窗口。隐藏、最小化及辅助覆盖窗口不参与选择。窗口矩形使用 ShareX 的边界计算，输出仍为屏幕可见像素，不保证还原被遮挡内容。

## 快捷键录入

- 所有可编辑快捷键共用 `ShortcutRecorder`，通过实际按键生成组合，不要求拼写名称；确认录入后仍需保存。
- 桌面 `BeginShortcutRecording` 使用自身 PID 申请 `shortcuts.record.start`。Host 暂时注销 WinOne 的绑定，返回一次性会话标识；其他程序的快捷键不受它管理。
- 完成、取消、失焦及卸载控件调用 `shortcuts.record.stop`，只允许结束匹配会话。Host 使用最新配置恢复绑定，录入期间的配置变更不提前恢复注册。
- 前端录入最长 20 秒；Host 保留 30 秒兜底，并观察所属窗口进程退出。收到旧队列事件时不执行模块动作。
- 松开修饰键后再结束录入，避免旧绑定在按键仍按住时触发。字母、主键盘数字、小键盘数字和 F1–F24 共用后端校验；F12 仍按系统保留键拒绝。
- `KeyboardEvent.key` 用于当前键盘布局；Shift 数字符号和小键盘数字保留对应键位，不把小键盘键变成主键盘数字。被系统截获的组合仍受 Windows 限制。
- 快捷键状态增加 `actionErrors`，按 `capture` / `pin` 归属展示，不把另一个模块的错误混入当前面板。

依据：[MDN KeyboardEvent.key](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/key)、项目已固定的 PowerToys `HotkeySettingsControlHook.cs`，以及现有 Windows `RegisterHotKey` 注册与冲突回归。
