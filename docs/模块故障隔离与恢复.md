# 模块故障隔离与恢复

2026-10-08。已接入真实 Host 与现有工具管理界面。普通安装、来源预览和完整升级协调仍按可选模块计划继续。

## 故障隔离

模块发现现在逐项保留错误，不因单个包损坏、失去信任、缺少登记、配置不匹配或包变更未完成而结束整个 Host。登记文件不可读时，从本机配置和模块状态中识别已知的可选模块；不从不可信包读取执行入口。没有可识别条目时保留全局登记警告。

故障条目只发布状态，不发布 Worker 路由。配置中心将其作为明确的不可用命名空间：保留原始配置、启用选择和恢复标记，拒绝修改该模块，允许其他配置正常提交。现有基础功能入口与 WinOne 日志保持可用。不把“不运行故障模块”写成“该模块已成功关闭”。

如果已有未完成的全局配置事务改动了该模块，事务继续保留，设置写入仍受恢复保护；Host 和日志可访问。恢复时重新验证旧的已提交配置，不采用未提交目标。全局配置文件本身无法读取或结构损坏时，仍拒绝覆盖原文件，不使用默认值掩盖损坏。

## 用户入口

工具管理显示不可用条目、已保留配置提示、可展开的原因，以及“重试加载”或“恢复旧版本”。隔离状态禁止开关操作；有包变更记录时使用恢复入口，不能把它当作普通“继续关闭”。中英、深浅色和窄视口布局已检查。

`modules.recoverPackage` 经统一配置队列串行执行，携带模块 ID、模块状态修订和恢复记录 ID。旧修订、对象变化或恢复记录不一致返回冲突，不重用过期操作。

## 恢复顺序

1. 重新读取登记与当前信任，验证文件、兼容性及已提交配置。
2. 对没有改变状态的准备记录，取消该准备；已经切换的记录则验证并恢复旧包绑定。
3. 需要资源恢复时，先持久保存关闭标记，再以未绑定路由的方式运行受控检查。准备阶段只允许 `RecoveryOnly` 许可，不能发布功能入口。
4. Worker 必须明确确认恢复并实际退出，才清除关闭标记。仅观察到进程已结束不算确认；诊断日志错误与真实进程退出错误分开处理。
5. 恢复统一配置和原启用选择，完成登记事务，最后发布模块路由。恢复检查进程随操作结束，不作为预热常驻。

失败时保留故障、未完成记录及仍需退出的恢复进程。再次启动遇到关闭标记，即使文件完整也继续隔离，不能用空闲 Worker 的关闭结果清掉标记。修复后可再次尝试；未通过签名、配置或实际退出检查时不会报告成功。

底层同时修复了卸载恢复的遗漏：已经进入应用或恢复阶段的卸载允许从空包绑定恢复原绑定；仍在准备阶段的异常空绑定继续拒绝。

## 证据

- 配置与生命周期回归覆盖坏文件、坏登记、坏配置、带/不带坏文件的待关闭状态、冻结数据、其他设置写入、未完成配置事务和恢复适配器。
- 真实 Host 使用签名测试 Worker，覆盖坏文件修复、准备中断、关闭标记中断、已切换卸载登记、配置事务未完成、恢复进程拒绝退出，以及新版本已切换但不受当前 Host 信任的旧版本恢复七类情况。验证日志读取、设置保护、旧数据与启用选择保留、重试后的实际调用和进程退出。
- 实际 Rust/WebView2 窗口通过故障显示、失败重试保留、设置页日志访问和修复后重载；8 组中英、深浅色、620/1280 视口布局无横向溢出。视口检查使用浏览器布局尺寸，不冒充多显示器 DPI 验收。
- 350 项前端测试、Go 源码包测试、相关静态检查和 69 项依赖声明核对通过；桌面前端与 Rust 宿主已构建。
