# AI 服务全量对齐当前上游（2026-11-14）

本次范围是当前保留的常用、自定义供应商、账号供应商和本地网关。Magpie 固定为 `ce2ce86ab43a185688556b5887efab6f1670c58b`，账号适配器固定为 `a410afe0d9a128d368711daf83ecf79a5d43b6c8`。不重新引入已按用户要求移除的独立对话、路由组管理、插件管理或全局用量页面。

用户要求所有模型能力默认跟随 Magpie；发现模型、勾选启用和普通保存均不得自行设置能力覆盖值。WinOne 保留原生界面、统一配置、凭据保护、窗口/进程所有权和网关模型访问边界，实际模型与供应商行为由对应上游实现负责。

## 根因与处理

原报错来自 `internal/ai/model_metadata.go`，不是供应商拒绝。它要求 `maxTokens <= contextWindow`。但上游明确允许原始目录中出现这种组合，例如供应商窗口 128,000、模型目录输出 384,000；`provider.OutputWithin` 只在展示窗口与输出这一对数值时收敛输出，实际请求另由原网关处理。WinOne 还漏用了这一展示函数。

另一个问题是 `RefreshModels` 将发现能力复制到 `ModelMetadata`，而请求又把整个映射作为用户设置安装。默认窗口、输出、思考、图像和价格因此可能变成长期覆盖。现在 `CatalogMetadata` 只保存模型报告，`ModelMetadata` 只保存用户修改；显示与请求使用不同的读取入口。

已有数据按随配置保存的目录基线迁移一次，用 `modelDefaultsSeparated` 标记。能确认等于原报告的字段解除覆盖，明确修改的字段保留；没有原报告的旧值不猜测、不删除。恢复默认清除用户覆盖，保留模型报告。原百分比压缩设置继续按实际上游窗口解释；新编辑使用 Magpie 的 Token 阈值。

续接核查还复现了 Host 的四任务限制、20,000 字／100,000 字节模型输入限制，以及凭据、翻译、生成层的 90 秒整轮超时。模型请求已移除这些近似限制，由原网关负责准入、窗口及等待规则；显式辅助预算和非模型翻译保持各自的边界。

共享运行程序的窗口所有者在启动前被确认。设置窗口关闭不会打断仍打开的结果窗口，最后一个结果进程退出后释放临时运行程序。保存供应商连接时，新请求使用新配置，正在返回的回复继续使用其原实例；回复结束后释放旧实例，不另加模型调度策略。
