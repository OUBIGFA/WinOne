# 安装启动检查的 learning.pending 修复

## 原因与范围

用户安装上一版时出现 `--check-ui probe failed: 启动检查不允许调用 learning.pending`。生产设置窗口启动时读取学习页面的待处理队列，而安装器的隔离 Host 没有登记该只读入口，导致安装检查主动失败。

本次只修改 `apps/desktop-mygo/app/probe_windows.go` 的启动检查：`learning.pending` 与既有待处理入口一样返回空 `core.Intent`。不启动 Anki，不运行用户任务，不放行 `learning.call`、上传、配置保存或未知命令。正常启动行为和安装器检查门槛不变。

代码修复提交为 `066529eba1ef9463bff8f5596d3a90101ac2df17`，已推送 `origin/main`。其他会话打包前须包含此提交并重新编译 `WinOne.exe`；不能复用修复前的桌面可执行文件。

## 三轮核对

1. 根因与权限边界：新增回归在修改前稳定失败，错误与用户报告相同；修改后所有启动检查相关单元测试通过。学习入口返回空队列，学习执行、上传和保存仍被拒绝。
2. 实际启动检查：旧交付程序在私有桌面上复现相同失败；修复后的实际程序通过 `TestNativeDesktopProbeUnderMaintenance`，包含安装器的 nonce/PID/路径/UIReady 握手、实际绘制及退出检查，维护标记保持不变，输入桌面未切换。
3. 包与改动范围：从已交付提交 `87d1c551` 的源码快照编译，避开当前工作区另一批 AI 升级改动。9,589 个受跟踪文件的逐字节比较中，仅检查实现与回归测试改变。从旧正式包复用全部载荷，只有 `WinOne.exe` 改变，其他 7,542 个运行文件逐字节相同；包含说明和许可证的 ZIP 对照为 7,544 个文件保持原样。重新生成清单和压缩包后，7,545 个包文件回读校验通过；安装器、卸载器和包清单的最终关联核对通过。

本次使用 `build/test-installer-ui-probe.ps1` 执行真实安装启动检查。该入口显式使用私有桌面和仓库内配置，不安装程序、不修改真实配置、不切换用户桌面、不请求提权、不连接网络服务。没有运行真实安装覆盖/卸载，不将启动握手通过扩展为所有安装场景已测试。

## 使用修复包

正式入口仍为 `dist/release/WinOne-setup.exe`，配套校验值和来源见 `release-info.json`。用户可以直接重新运行修复后的安装包；本次不清理用户报错中提到的安装备份，也不要求手工删除真实安装或配置。
