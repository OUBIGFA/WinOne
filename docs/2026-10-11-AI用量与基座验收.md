## 故障根因与修复

| 问题 | 已确认根因 | 修复与证据 |
| --- | --- | --- |
| 会话页显示 `unsupported` | 前端用 `captureCall("chat.usage")`，实际进入 `capture.chat.usage`；Rust 的 Chat 白名单本来已支持 `usage` | 会话统计和上下文标题改用 `chatCall("usage")` / `chatCall("catalog")`。`ai-usage-routing.test.tsx` 保留真实 bridge，仅替换原生传输边界；修前两项失败，修后通过 |
| 账号可用但额度显示占用错误 | 账本筛选使额度组件卸载重建，旧读取尚未结束又发新请求；Host 对读操作立即尝试独占，竞争直接报错 | 保持额度读取生命周期并合并在途请求；账号仍串行访问，读操作改为可取消等待。`ai_account_queue_windows_test.go` 覆盖等待、释放、取消及真实 worker 启动失败 |
| 额度接口失败后看起来仍成功 | Magpie 在 503 后保留上一份额度，用 `asOf` 标记历史读数并清空原错误 | 主动额度请求传 `provider.Asked(ctx)`；`asOf` 明确标记刷新失败，界面显示历史时间，保留历史能力，不伪造新读数或零额度 |
| 新基座账号测试读错目录 | 新上游优先读取 `CODEX_HOME`；旧测试只改 `USERPROFILE` | 测试同时绑定私有 Codex 目录。产品原有子进程环境仍移除外部账号变量；构建测试也隔离账号环境并复用 Go 依赖缓存 |

账号额度集成测试从真实 Host 处理器启动真实编译的短命 worker，通过链接参数将其唯一 Codex 测试端点指向本地 HTTP 服务。成功响应为 **25% 已用**；随后返回 503，回执包含明确失败标记及历史时间。测试使用合成凭据，未请求真实供应商。
