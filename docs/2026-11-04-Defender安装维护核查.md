## 检测与来源

- 2026-11-04 12:34:25，Defender 事件 1116/1117 将测试安装器解压出的 `WinOne.Maintenance.exe` 判为 `Trojan:Win32/Bearfoos.A!ml`，随后隔离。告警发生在此前安装器的卸载中断恢复测试中，不是 SmartScreen 的“未知发布者”提示。
- 原 `build/windows/installer.nsi` 在首次安装和恢复时把包内 `WinOne.Host.exe` 改名为维护程序，卸载时再复制已安装 Host。该副本同时包含普通后台、登录启动、账号和 UI 控制等维护并不需要的入口。
- 旧 Host 也被阻止读取。使用全新的 Go 编译缓存重新构建，仍在编译器输出处被拦截，因此不能把问题解释成仅有旧文件/缓存损坏。
- Host 实际引用的 **12 个外部 Go 模块**按 Go `dirhash.HashDir` / `Hash1` 与 `go.sum` 核对一致。`go mod verify` 因本地 `winone/modules/wintray` 替换模块缺少 ziphash 而中断，未记为通过；3 个本地来源模块不具备上游下载摘要。没有对全部本地源码或编译器完成独立安全审计。

## 实施与完整保留的维护能力

| 原能力 | 当前实现 | 验证 |
| --- | --- | --- |
| 安装锁与配置锁、拒绝占用 | `internal/installguard.Hold` 复用 `maintenance`，仍保留 Host 管道预约 | 实际守护协议、完整安装矩阵 |
| 维护程序必须位于安装目录外 | 原路径/目录树检查移入共享包 | 单元测试，拒绝时尚未打开配置目录 |
| 就绪事件、owner 进程句柄、提前退出检查 | 原 `HoldUntilOwnerExit` 及 NSIS 守护函数，协议不变 | ready / failed / lost / released / closed-owner-alive 五种原生场景 |
| 卸载还原与原始配置保留 | 原 WinTray 异步 `uninstall.prepare`、管理员授权与 Explorer 菜单所有权检查 | 14 次隔离操作，配置和额外文件保留 |
| 安装失败回滚、显式旧修复与卸载恢复 | 原 NSIS 与 Go 更新事务不变 | 两处回滚、坏记录拒绝、修复失败保留、成功修复、两次卸载中断恢复 |
| 旧 Host CLI | Host 转调同一共享实现，保留兼容 | Host 回归及完整载荷集成测试 |
| 新的维护边界 | 专用 `build/installer-maintenance`；无参数或 Host 运行模式不能启动后台，必须显式提供配置目录与安装器 owner | 参数表与实际 EXE 拒绝测试，未生成配置文件 |

安装器和卸载器嵌入的是同一份专用维护程序，不再执行改名的完整 Host。专用 manifest 使用 `asInvoker`、`uiAccess=false` 和长路径声明；非 UI 程序在释放管道、锁后正常退出，不引入 Host 的 UI DLL 退出处理。普通 Host 全部功能保留，没有改名、填充、手工修改二进制或改用其他持久化渠道来绕过检测。

## 可复用扫描入口

- `build/verify-windows-security.ps1`：检查 Defender 正常运行、实时和行为防护，执行自定义扫描，记录原始输出、文件/清单 SHA-256、情报版本与现有策略。
- 自定义扫描使用微软说明的 `-DisableRemediation`：**只对本次扫描禁用处置，不关闭实时防护**，忽略文件排除并扫描归档，检出结果在命令输出中呈现。它不恢复隔离样本、不添加允许规则，也不修改系统防护设置。
- 不以退出码 0 单独判定成功：必须有已完成的 `found no threats`，文件扫描后仍可读且摘要一致。任何异常都清除通过状态。
- `build/build-installer.ps1 -VerifyWindowsSecurity` 在编译前扫描完整展开载荷和三个帮助程序，编译后扫描安装器和匹配的卸载器。
- 正式测试 `tests/windows-security.ps1 -RunSystemChecks` 覆盖干净文本、缺失目标、扫描后目标消失和保留已有报告。后置读取失败用只操作精确测试文件的替身模拟，不创建恶意样本、不修改 Defender；**先复现错误通过状态，再修正并通过复验**。
