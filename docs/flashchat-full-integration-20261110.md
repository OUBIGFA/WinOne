## 原因与修复

旧 Go 移植省略了媒体能力，使用独立房间命名空间和自定义文件协议，默认只有 STUN。本轮入口改为完整上游 `708fefdcc3ac0f5fc2ef2ca9ce1cc1b6a9f46c74`，保留上游通信实现，统一房间命名空间；文件沿用加密 WebTorrent，并使用与聊天相同的网络配置。

原版默认公共中转在当前测试中返回认证失败。新增 Jami 官方公开中转配置，包含 TCP 连接方式。它是公开外部服务，不是 WinOne 自建服务，也没有 WinOne 可承诺的持续可用性。只取得候选地址不算连接成功。

电脑保持现有网络，手机 Safari 使用移动数据和同一构建页面，双方实际收到文字。电脑证据记录收到“手机已经连接”，手机结果由用户确认。临时 HTTPS 页面经单独授权开放，完成后关闭。此结果证明当前两条网络之间完整通信实现可工作；不等于两台实体 Windows 电脑已经远程实测，也不证明原官网的不同配置可用。

客户端邀请流程是复制房间链接，在另一台 WinOne 闪聊的“房间名称或邀请链接”中粘贴加入。原版二维码、网页链接和 SDK 保留，但直接在原官网打开的跨网成功率仍受官网配置影响；本次不建立新的公开网页入口。
