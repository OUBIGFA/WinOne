# 原生窗口启动优化（2026-11-07）

状态：启动改动与完整功能组合已通过验证，安装器生命周期验收通过。统一交付见 [交付记录](delivery-20261107-startup.md)。

## 实际变化

普通不透明原生窗口在 D3D11 设备创建期间，用 MyGo 原有 CPU 渲染器绘制完整页面并接收输入。设备就绪后，UI 线程创建交换链并交给 GPU 绘制。两条路径使用相同页面、布局、事件和输入状态；切换不重建控件、不清焦点或草稿。关闭窗口时，未完成的设备初始化结果由取消路径释放。透明材质和嵌入网页的合成表面保留原流程。

此前分段诊断显示，首次等待主要发生于显卡驱动的 `D3D11CreateDevice` 调用；诊断样本约 275–490ms，DLL 加载约 2–4ms，绘制与提交约 8–20ms。仅提前并行创建设备但仍在首帧等待的方案，前后收益不稳定，未采用。

本次不使用常驻窗口、进程外预热、启动延时或过渡画面。就绪标记仍在实际 Host 数据、页面异步工作和 UI 回调完成、原生绘制之后发出。硬件加速接管另用 `-ObserveGPUHandoff` 诊断，不把日志诊断混入预算样本。

线程依据：[Microsoft：Direct3D 11 多线程介绍](https://learn.microsoft.com/en-us/windows/win32/direct3d11/overviews-direct3d-11-render-multi-thread-intro)。只有设备和立即上下文的创建移到后台，后续上下文调用、窗口、交换链和绘制仍在 UI 线程。

## 统一验收中修复的旧问题

- Host 默认配置保护的测试原先假定本机一定存在安装登记，便携环境会错误失败。生产入口不改变判断规则；测试使用受控读取边界，并以独立注册表项验证无登记、不同安装、正确安装和显式目录，不读取或修改用户登记。另去掉测试遗留的当前目录变更。
- 程序管理对两个异步关闭窗口逐个确认时，400ms 轮询会累积不必要等待。确认间隔改为100ms，最大验证跨度仍为3.6秒，保留进程存活检查、关闭能力判断和共享启动预算。真实 OWNDC/CLASSDC 自动/手动场景三轮通过。
- “进程退出不能算收进托盘”的测试改用自有窗口消息要求夹具进程退出，仍验证真实进程终止。键盘焦点与 Esc 派发由原独立原生用例覆盖，避免用户前台变化使这个进程生命周期测试不执行目标场景。
