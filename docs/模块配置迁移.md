# 模块配置迁移

2026-10-08。已接入本地模块更新、失败恢复和保留配置重装。迁移以签名包中的数据规则执行，不加载包内脚本或迁移程序。

## 包内规则

元数据 v3 在 settings 中增加 migrations。以下仅展示迁移相关字段，其余字段仍按模块包契约填写：

```json
{
  "schemaVersion": 3,
  "module": { "settingsSchemaVersion": 2 },
  "settings": {
    "schema": "settings.schema.json",
    "defaults": "settings.defaults.json",
    "migrations": [
      { "from": 1, "to": 2, "patch": "migrations/v1-v2.json" }
    ]
  }
}
```

补丁采用 RFC 6902 JSON Patch，支持 add、remove、replace、move、copy 和 test。示例：

```json
[
  { "op": "add", "path": "/label", "value": "migrated" }
]
```

规则及补丁都必须列入签名库存。最多 32 段，每段最多 256 项操作、256 KiB；每个起始版本只允许一个后继，版本递增且所有已声明链路必须到达目标版本。路径使用 RFC 6901 转义，拒绝无效转义和控制字符；不接受负数组下标，不自动补建缺失父路径，不忽略删除缺失项。配置及每段输出均受 2 MiB、UTF-8、唯一键和嵌套深度校验，复制增长有界。

使用 github.com/evanphx/json-patch/v5 v5.9.11，版本、校验和及 BSD-3-Clause 许可证已锁定。原始数值精度保留；迁移错误只给出阶段或字段位置，不输出实例值。没有迁移链、规则失败或输出不符合新 schema 时保留原配置并拒绝更新。

## 预览与提交

预览只在内存中转换配置，显示配置格式版本和最多 32 个涉及的字段路径，不显示配置值。确认后重新验证包、修订和当前配置；配置迁移不能改动其他模块、全局设置或启用意图。

Host 在用户目录 package-migrations 下保存原配置、候选配置、配置修订、前后 schema 版本和包摘要。包变更记录 v3 绑定该备份的 SHA-256。更新过程中模块保持隔离，新版读取只供检查的候选投影；新版校验、资源恢复和退出均确认后，才写入统一配置并提交包切换。

配置中心仅持久化当前隔离命名空间，其他字段保持不变。这个数据提交不调用普通模块/全局应用钩子；投影、候选检查和资源回退由外层包事务负责。原配置备份一直保留到包事务结束。

## 失败与重启

迁移失败、候选无效或配置落盘失败会恢复旧包和旧配置。若进程在新配置写入后、包提交前中断，下一次 Host 从摘要匹配的备份恢复当前模块，并保留后来修改的全局或其他模块设置。

备份缺失、被改动、包摘要不符或资源恢复未确认时，模块保持隔离。回滚先验证目标配置，再清除属于该迁移的未提交配置；不丢弃不相关的配置事务。已结束事务的备份随退役文件记录送入回收站，失败保留重试入口。

卸载后重装时，配置中心读取保留数据的 schema 版本，通过同一迁移链转换；提交失败仍保留原保留数据，成功后保持模块关闭。跨设备导入的 deferredModules 仍走独立导入预览，不混用本机保留配置。
