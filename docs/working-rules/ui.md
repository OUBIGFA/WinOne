# 界面与交互约定

仅在任务涉及界面布局、图标、导航、主题、语言、快捷键和错误反馈时读取。本文件承接原项目 AGENTS.md 的约定，不改变需求。较新的明确约定优先；历史计划中的“当前顺序”须结合相关开发状态核对。

- UI 与设计工作一律禁止从零自绘。先核对优秀开源项目的实际实现，优先直接复用，再通过现有组件组装或必要微调接入 WinOne；记录来源、版本、许可证与改编范围。不得用自己重画的近似界面冒充复用。现有成熟原生组件和 shadcn/Base UI 的组合属于组件组装，不另绘交互控件。
- 用户于 2026-10-12 反复明确：Chat **右侧边栏**必须完整、原样复用 `liuminxin45/ChatGPT-Desktop-UI` 的实际右栏设计，包括 `examples/demo/ClientPane.tsx` 的 `BrowserPanel` 胶囊边框、标签、加号、地址栏、工具入口和菜单。不得拿通用 Tabs 重新拼出另一套右栏，不得保留旧右栏组件、旧布局或旧外观覆盖。只做真实 Host 数据、回调、语言与既有功能状态适配；资源入口和内容必须保留。此项范围是右侧边栏，不是整个 Chat 换版。正文另按上游 `ConversationMessage`、`AIResponse` 和示例正文布局直接复用，保留完整展开工作过程和收纳动作。
- Chat 输入区保留与正文的底色区分及渐变过渡。拖动输入框只改变输入框高度，正文位置、视口高度与滚动位置不随之变化，允许被输入区覆盖。新会话输入框固定底边向上增高，Logo 同步向上移动、保持相对留白，不被输入框覆盖。Git 分支栏只在首次打开、项目变化或手动刷新时读取，窗口焦点变化不触发重读。
- AI 服务路由页按 2026-10-12 最新要求直接使用 Magpie 原版设计和版式，包含模板卡片、底色、字号、间距与对齐；撤回本轮定制外观。宿主只做必要的主题、语言和嵌入尺寸适配。
- 文件与目录链接中的“资源管理器集成”只显示一个开关、对应标题和说明；避免与下一分组叠加分隔线。失败或登记冲突仍须显示实际原因。
- Chat 输入区渐变只作用于聊天内容区域，不能覆盖两侧边栏。右侧面板填满用户分配的宽高，不继承通用 `aside` 的固定宽度和内边距；标签栏不显示横向滚动条。新会话 Logo 与输入区保持明显留白，当前范围为 128–192 DIP。
- 用户指定复用某项功能时，界面必须恢复该功能的全部入口、选项、快捷标签/预设按钮、管理操作和状态反馈，不得自行精简。每个可见控制必须接通保存与实际执行；只保留外观、删掉行为不算复用完成。布局、位置与便捷操作按用户指定上游核对，不按 Agent 个人偏好另排或省略。
- Chat 结合 Cindy 的项目、输入与权限交互和 LobeHub 的成熟对话交互，统一为 WinOne 的主题、字体、状态反馈及双语资源。新设计先从这两者的可复用实现选型，不为了“结合”重复添加相同入口。
- 好的交互动效可直接复用，优先沿用所选开源组件的展开、收起、菜单切换和发送状态过渡；保留键盘操作及系统减少动效设置，不为装饰另写动画。
- 同一段可见间距只能有一个控制点。思考到正文的总间距由阅读内容容器控制，子项不得叠加底部外边距或重复 padding；使用实际渲染尺寸检查，覆盖展开/收起、生成中/已完成、普通段落/标题及不同窗口宽度。
- 长思考展开后，在思考内容区域的底部提供固定、随时可操作的收起入口；它不随正文滚出可视区域，只在思考内容确实超长时显示。Chat 与共享结果页使用同一计时、长内容判断和折叠行为。

- 页面顶部不再显示重复的大标题，保留页面内必要分组与操作；界面统一写作「AI 服务」。划词设置标签顺序为「工具栏」「常规」，AI 服务的「本地网关」紧随「默认 AI 服务」。结果页内容允许再次划词；模型列表以两格缩进表达供应商从属关系。置顶快捷键作用于鼠标悬停的可见顶层窗口，无需激活前台。
- 「便捷功能」位于「程序管理」之后，首个标签为「置顶功能」。首页与侧栏使用同一顺序；置顶保留独立启停、原配置及快捷键。页面有未保存修改时禁用启停操作，避免刷新状态丢失草稿。
- 模块设置的快捷键分组使用 Lucide SendHorizontal；两个助手的代码动作统一使用 Lucide CodeXml，设置预览与实际工具栏保持一致。
- 自定义供应商没有品牌图标时默认使用 Lucide Layers；AI 服务的“自定义供应商”标签页使用 LayersPlus。所有拖动把手使用 GripVertical；总结动作统一使用 ListCheck，覆盖快捷助手、划词助手、设置预览及其他对应入口。
- 标签切换时保留共用说明与标签组的位置；标签专有说明、加载和错误反馈放在标签组下方，不能通过隐藏上方内容使导航跳动。验收须比较切换前后的坐标。本地网关按供应商分组显示名称和对应图标，模型显示名称、模型图标及启用勾选，不显示内部路由 ID；保存后的选择同时限制第三方模型列表和调用，全部取消时不开放任何模型。
- 桌面迁移必须一比一保留原版设计、布局、功能分组和完整功能，直接复用项目已规定的组件与本地图标；禁止自绘控件、手绘替代图标或另造一套外观。现有设置界面的 shadcn/Base UI、Lucide 及共享样式是还原基准。程序列表和详情各自在区域内滚动，程序管理页面及其导航、工具栏不随列表滚动。旧 Rust 自绘预览不作为设计或交付基准。
- 还原以仓库最新版 UI 为准，不参考旧版布局回退。程序列表的每个程序使用单行，图标、名称、托盘收纳、更换和序号下拉菜单同排，不拆成上下两行；排序不改回上下箭头按钮。
- 主界面侧栏支持连续拖动调宽，可一直拖到 64 DIP 的仅图标栏；记住宽度，保持拖动把手可用以便拉回。图标按钮可展开或收起，窄窗自动显示图标栏。首页模块顺序与侧边栏共用同一排序。折叠与展开保留图标尺寸、行高和坐标；顶部收起按钮与导航图标共用中心线。检查须对比切换前后，不仅检查单一状态的居中。
- Rust 桌面直接采用仓库最新版 UI 源码，复用现成页面、组件、图标、布局和功能；迁移集中在桌面宿主与接口适配，不另写一份复刻界面。
- Logo 必须保留完整原图、留白、宽高比和图案形状；圆形只应用于外层容器。用户说缩小 Logo 时，调整容器尺寸与占位，原图使用等比适配；禁止裁掉原图留白、裁切图案、拉伸或改变 Logo 比例。
- 通用服务动作与服务预设入口使用 Lucide PlugZap（插头＋闪电）；供应商默认头像使用 Layers，自定义供应商标签页使用 LayersPlus。添加供应商按钮使用 Plus，已识别供应商与模型使用各自品牌图标；用户设置图片头像后优先使用原图。
- 采用 Windows 装饰的顶层窗口，其外框和圆角由 Windows 统一负责，客户端根视图只填充背景。划词工具栏、OCR 和翻译结果共用 `windowSurface` 与 `PrepareWindowFrame`，不得再各绘一层根边框。网页弹层只由 Popup 本身绘制一层边界，不再包同尺寸描边；正常的内部控件边框、分区线和键盘焦点环保留。
- 所有 WinOne 原生菜单及其子菜单统一字体、间距、边框、选中/禁用状态和深浅色；复用共享样式，不逐菜单另设视觉规则。保留原生键盘、焦点、屏幕边界与高对比度支持。
- 截图操作界面及后续新增模块采用成熟原生控件与 WinOne 统一风格，性能优先。置顶功能、程序管理保留现有界面和实现，不做原生化迁移，不为此重写现有共享设置壳。既有信息层级与交互要求继续按 `docs/体验重构计划.md` 执行。
- WinOne 统一提供原生控件封装、设计令牌、图标、主题、语言、导航和错误反馈。模块复用共享界面宿主及运行时，按需加载与释放；不得各自保留独立产品UI或各带一套常驻UI运行时。迁移须保持已有功能、配置兼容、快捷键、未保存保护和恢复能力。
- 布局、入口和功能选项优先保证易用、无歧义、指示清晰及符合预期；以完整用户任务和权威交互依据验收，不以实现方便或单项测试代替体验。
- 主题、语言只在 WinOne 全局设置中提供入口。面向用户展示的布局预览必须遵循正式信息架构，不把测试按钮混入公共页头或各模块。
- 所有可配置快捷键统一使用按键录入控件，不要求用户拼写组合名称；录入期间保护现有快捷键，退出录入必须恢复注册并显示冲突。
- 全局设置提供“打开 WinOne”快捷键，默认 Alt+A，可修改或清空；与模块启停独立，沿用当前会话的普通/管理员实例路由，不重复创建界面。新默认与已有用户绑定冲突时保留原绑定并显示冲突。
- 模块页面正在读取设置或读取失败时，全局设置中的 WinOne 日志入口仍须可用；模块不再各设日志入口。加载完成不改变用户当前选择的设置标签，无日志时明确显示空状态。
- 页面、字段与操作错误统一使用 WinOne 原生状态反馈组件，明确原因与下一步；保留的网页界面继续使用 Notice/InlineError。非阻断提示使用中性样式，重试等普通操作不继承错误色。
- 主动打开 WinOne 时激活到前台。关闭程序管理复用现有权限；权限确实不足时，每次关闭操作最多请求一次授权，不逐程序重复请求。
- 模块设置布局：快捷键独立置于顶部；截图的截图后、文件名模板、滚动截图设置归为同一标签组，设置页不再显示截图操作按钮和最近截图预览；“置顶功能”下方直接使用常规设置、高级设置，不增加“置顶设置”中间层。程序模块对用户统一称为“程序管理”，内部兼容标识 wintray 保留。
- 所有模块使用同一设计系统、导航、主题、状态反馈和中英双语资源。WinTray 全部功能必须可在对应面板设置；快捷键按模块/动作配置，WinTray 不设无实际需求的快捷键。
- 高频操作放主页面，低频与复杂设置放清晰标注的二级页面；文案只说明操作、结果和必要限制，不暴露实现细节，不堆叠说明。
- 面向用户的界面禁止使用内部实施/迁移式文案，例如“从此版本开始统一记录”“较早的分散记录不计入此页”。版本迁移、记录架构、内部处理范围写入开发或兼容性文档；界面只说明用户的操作、可观察结果及使用所必需的限制，不以内部实现过程解释产品状态。
- UI 组件、图标、字体和界面资源优先本地打包，按需引入并锁定版本/许可证；运行基本功能不得依赖 CDN、在线字体或组件网站。

实现资料按需选择：[统一体验与设计依据](../统一体验与设计依据.md)、[体验重构计划](../体验重构计划.md)、[Rust桌面UI迁移](../Rust桌面UI迁移.md)。不要递归展开全部链接。
