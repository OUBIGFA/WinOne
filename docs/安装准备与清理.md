# 安装准备与清理

2026-10-08。安装、更新现在在暂存目录创建后、载荷写入前记录准备阶段的归属。准备阶段失败不再只留下日志；工具管理的现有清理入口可以发现对应记录。

## 记录与接管

产品 Host 使用 `Registry.StageArchive`，复用原来的签名、兼容性、文件与暂存验证。准备条目进入回收账本 v3，标记为 `kind: preparation`，绑定操作 ID、模块、版本、目录 ID 和清单摘要。账本无法写入时不写入载荷；已经创建的空目录保留并报告错误。

迁移备份的摘要由同一套规范化和编码计算。Host 先把摘要绑定到准备记录，再保存备份，最后开始包变更。若备份保存或包登记失败，暂存文件与备份仍有可恢复的归属信息。

登记或包事务接管目录后，清除的仅是准备条目。真正的包文件和备份由已登记状态或包变更记录负责。显式清理先同步这种接管关系，不回收待处理事务仍需要的备份。

## 清理边界

- 完整、签名及文件验证通过、没有登记或待处理事务引用的暂存包，使用现有回收流程。
- 文件变化、缺失、不完整、目录链接或无法核对归属时保留文件并报告；不降级为永久删除。
- 已登记的目录不因准备记录残留而被清理。
- 页面状态仅显示安装暂存或旧文件待处理，不把失败的安装称为更新成功。
- 首次安装可能只有准备账本而没有包登记；整应用升级预检也必须校验这种账本，拒绝未知格式。

`StageArchive` 的无登记原始接口继续用于底层夹具；产品安装与更新入口使用带准备记录的 `Registry.StageArchive`。记录不包含用户配置内容；迁移备份仍留在配置中心的专用目录中。

## 已验证与剩余工作

实际编译的 Host 验证了只有准备账本时的只读预检、未知格式拒绝和控制文件保持；Rust 桌面与 Host 候选构建通过。回收站后端没有改变，本轮未重新执行会写入仓库外系统回收站的测试；不将这些记录称为本轮完整安装/回收验收。

旧版本没有准备记录的目录现由 `UntrackedStages` 有界发现。状态读取只检查目录名和控制记录；显式清理时排除登记、待处理事务及既有回收引用，再验证完整回执、签名和全部文件，才补入准备账本。空目录、缺回执、文件变化、未知发布者或额外内容保留并说明原因，不能仅凭目录名前缀删除。

旧迁移备份另行核对当前旧包摘要、当前配置、配置格式，以及已签名的新包迁移结果；全部一致才关联到对应暂存包的清理记录。配置或备份有变化、缺失对应包、仍有恢复事务时保留。无法核验的备份也会阻止相关暂存包被提前回收，避免删除最后的核对依据。只有备份而没有包目录时显示待处理，不报告清理完成。

目录发现、重复检查、文件篡改、失去信任、取消、旧备份匹配与不匹配、待恢复备份保护等回归通过。实际 Host 通过正式 `modules.snapshot` 和异步清理命令验证不可核验内容的可见性、文件/配置保持与正常退出。首次实进程测试误用了内部状态方法；改为产品实际公开入口后通过，未改产品接口适配测试。
