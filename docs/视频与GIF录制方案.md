请在当前截图软件项目中新增**屏幕视频录制（MP4）与动图录制（GIF）模块**，直接复用项目中现有的截图框选区域坐标。请严格按照以下技术规范进行代码设计与实现：

### 1. 整体架构与依赖约束

- **零外部进程依赖**：严禁调用外部 `ffmpeg` 命令行进程，严禁在磁盘生成临时序列帧图片（如 `.png` 文件夹）后再合成。所有捕获、去重、编码必须在内存/显存流中实时完成并流式写盘。
- **核心依赖选型**：
  - 屏幕捕获与硬件编码：使用 `windows-capture`（Windows 原生 WGC/DXGI + Media Foundation 硬编；若为 C# 则用 `ScreenRecorderLib`；若需跨平台则用 `scap`）。
  - GIF 高画质编码：使用 `gifski`（静态库集成，流式接收 RGBA 帧写入磁盘）。
- **与现有截图模块对接**：直接接收截图选区输出的 `(x, y, width, height)`、目标显示器标识、输出格式（`MP4` / `GIF`）、目标帧率（MP4 默认 30fps，GIF 默认 15fps）以及需隐藏的窗口句柄（录制时排除截图工具自身的悬浮工具栏）。

### 2. 捕获层与边界安全处理

- **奇数像素强制对齐（防硬编崩溃）**：截图框选出的宽高极可能是奇数，而硬件 H.264/HEVC 编码器（YUV420p/NV12）要求宽高必须为偶数。进入捕获裁剪前必须强制向下取偶：
  `aligned_width = width & !1`
  `aligned_height = height & !1`
  并限制最小有效录制尺寸不低于 `16x16`。
- **DPI 物理像素对齐**：确保传入底层捕获 API 的坐标已乘上当前显示器的 `scale_factor` 转换为物理像素坐标。

### 3. 静止帧剔除与体积控制（核心：降低 50%~80% 文件体积）

在捕获回调与编码器之间实现轻量级 **VFR（可变帧率）静止帧过滤器**：

- **极速帧比对**：对当前帧与上一有效编码帧做跨步网格抽样比对或行级快速 Hash（单次比对耗时必须 `< 0.2ms`，严禁全图逐字节慢速加密哈希）。
- **动态跳帧与 PTS 累加**：
  - 若画面未变化，且距离上一编码帧未超过最大关键帧保活间隔（如 `1000ms`），则**直接丢弃当前帧**，不送入编码器。
  - 下一帧画面发生变化时，使用其真实的系统单调时钟差值作为时间戳（`PTS` / `Duration`）送入编码器，实现画面静止时文件体积零增长。

### 4. 支持 2 小时+ 超长录制的稳定性设计（防 OOM、防丢文件）

必须确保连续录制 2 小时以上时内存占用恒定（不超过 60MB）且绝不丢数据：

1. **有界通道与背压（Backpressure）**：捕获线程与编码线程之间必须使用有界队列（Bounded Channel，容量限制为 `8~12` 帧）。当编码繁忙队列满时，在捕获端安全丢帧并顺延 PTS，严禁使用无界队列导致内存暴涨。
2. **内存缓冲池复用（Buffer Pool）**：预分配固定数量的帧缓冲区（如循环复用 12 个 `Vec<u8>`），在捕获端与编码端之间传递所有权并归还池中，避免 2 小时内产生成百上千次大块内存分配与释放。
3. **高精度时间戳与暂停补偿**：使用 `std::time::Instant`（64位纳秒精度）计算 `PTS = now - start_time - total_paused_duration`，严禁通过 `帧数 * 帧率倒数` 累加时间（防止长时录制音画或时长漂移）。
4. **流式落盘与磁盘空间熔断**：
   - MP4 编码器必须流式写盘，定期 Flush 缓冲；定期检测目标磁盘剩余空间，当剩余空间 `< 200MB` 时自动触发安全停止并保存文件，防止磁盘写满导致文件损坏。
   - GIF 模式增加软限制保护（如单次录制达到最大时长或帧数阈值时触发提醒或自动收尾）。

### 5. 双引擎编码参数配置

- **MP4 引擎**：调用系统硬件编码器（H.264 / HEVC），启用动态帧率（VFR），保证桌面文字边缘清晰且静态画面不占码率。
- **GIF 引擎**：使用双线程运行 `gifski::Collector` 与 `gifski::Writer`，默认 `quality = 85`，根据去重后的真实帧时间戳计算动态帧延迟（Delay）直接流式写入 `.gif` 文件。

### 6. 对外暴露的接口生命周期

请封装并暴露给现有截图业务层以下接口：

- `start_recording(config)`：初始化选区、偶数对齐、启动捕获与编码线程。
- `pause_recording()` / `resume_recording()`：记录并累加暂停耗时偏移量。
- `stop_recording()`：停止捕获 -> 排空有界队列剩余帧 -> 写入文件尾（Finalize） -> 释放缓冲池 -> 返回录制结果（文件路径、体积、总时长、实际编码帧数、跳过的静止帧数）。
- `cancel_recording()`：中止线程并删除未完成的输出文件。
