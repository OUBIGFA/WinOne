# WinOne 设置设计语言

版本：1.5 · 补充日期：2026-10-17。适用：WinOne 非 Chat 的设置与工具管理页面。

> 看得出分区，读得懂选项，找得到操作。简洁来自组织，不来自缩小字号、删除功能或把重要信息藏起来。

## 1. 依据与取舍

本轮读取了当前官方页面、Apple WWDC26 的公开逐字稿，以及已固定的开源组件源码。以下区分**来源原则**与**WinOne 自定规则**；网页的更新时间、组件宣传、启发式评审都不等于 WinOne 已通过用户测试。

| 来源 | 本次核实的原则 | 对 WinOne 的应用 |
| --- | --- | --- |
| [Apple HIG · Layout](https://developer.apple.com/design/human-interface-guidelines/layout) | 按重要性排序；对齐便于扫描，缩进表达从属；用留白组织关联；随实际可用空间和文字大小重排 | 设置从上到下阅读；组间距大于组内距；父开关的子选项缩进；窄分栏改为单列 |
| [Apple HIG · Settings](https://developer.apple.com/design/human-interface-guidelines/settings) | 合理默认值；稳定的分区导航；任务选项就近；不要重复系统级选项 | 主题和语言只在全局提供；保留原默认值及配置；快捷键置于模块顶部；不把操作挪去无关页面 |

| [NN/g · Memory Recognition and Recall](https://www.nngroup.com/articles/recognition-and-recall/)（2024） | 展示可识别的选择和上下文，降低用户回忆名称与功能的负担；图标不能代替必要文字 | 复用已被用户认可的截图选择块，保留短标签、可见边界和单选状态；导航图标与起始页面菜单保持一致 |
| [Fluent 2 · Layout](https://fluent2.microsoft.design/layout) | 间距表达关系；过密内容会被当成整体而跳读；4px 基础步进；以可用区域决定重排 | 定义共享间距令牌，不逐页叠加 margin；控件保持 Windows 鼠标/键盘习惯 |

| [NN/g · Visual Hierarchy](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)（2021） | 尺度、对比与接近性构成层级；过多颜色、边框和相同权重削弱重点 | 不以卡片套卡片或强阴影区分所有内容；组标题与字段标签不再同级 |
| [NN/g · Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)（2006） | 高频和低频功能需正确分层；入口必须有信息线索；过深披露会迷路 | 保留所有能力；不以“高级”兜底隐藏所有不易理解的功能；限制额外展开层数 |

| [WCAG 2.2 · 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | 普通文字对比度至少 4.5:1；指针目标至少 24×24 CSS px 或符合间距等明确例外 | 辅助文字仍可读；控件通常 36–40px 高；图标不等于命中面积；保留键盘焦点、拖动替代和缩放重排 |
| [open-claude-ui](https://github.com/Caho1/open-claude-ui)，核对提交 `02d021fceaf2a907f9e63a8125621bdda1b85d60`，MIT | CDS 2.0 的时长/曲线、组件圆角层级、弹层显隐与加载扫光；公开逆向整理的来源与许可已核对 | 适配现有设置和 Win32 菜单：200ms 展开、120ms 收起、60ms 按下反馈；保留 WinOne 字体、语义色及原生键盘行为，减少动态效果时停用动效 |

2026-10-16 的用户反馈有三条，均已落实：认可的是"敢于重组交互形式"，而不是某一种控件本身；设计语言必须全局统一，不能只改被点名的页面；黑白灰只约束软件层级的强调色，用量统计、模型标签、文件与目录链接底色这类有意义的数据颜色必须保留。据此本轮新增 open-claude-ui 的细节核对，并把颜色规则拆成"界面层中性、数据层保色"两层。

“最新”用于本轮读取的当前 HIG/Fluent 与 WWDC26，不把 NN/g 的经典文章误称为新研究。4px、40px 或一屏几个字段不是心理学定律，以下为项目选择，需用真实任务修正。

Claude Code 资料于 2026-10-15 从 Anthropic 官方仓库核对。该文件最新修改提交为 dbdd79cebfae5891f5b0fab6f7773ea520d289a7（2026-09-02），内容对象为 a5333457c414d20d625f307df945842c0952ecc3；anthropics/skills 的同名文件内容一致。这是公开的设计 Skill 指南，不是完整的 Claude 产品设计系统。这里只参考设计细节，不安装或执行外部技能。

### 常规页选择块的取舍

2026-10-15 的直接用户反馈是：常规页主题、语言仍像堆字，而截图的“截图后编辑／截完保存”选择块简洁且容易辨认。这是本项目的真实反馈，不是多用户研究。以下取舍结合该反馈、上述设计准则及真实窗口操作验证；尚未开展新用户任务观察，不声称完成速度或满意度提升了某个比例。

- 直接复用截图的 `SettingsChoice`（本地 shadcn Label + Base UI RadioGroup），不绘制另一套控件或装饰性小窗。分组保持平面布局，只有可点击的选项有边界；选中同时由单选标记、边框与底色表达。
- 主题、语言各自成组；侧栏与起始页面归入“打开界面时”。语言使用各语言自己的名称，起始页面使用实际导航目录及图标，不删选项。
- 一组选择在足够宽时同排，不足时全部单列；不留下“两项在上、一项在下”的孤立选项。整块可点击，保留方向键、焦点、禁用、保存失败后的原值和重试能力。
- Microsoft 的主题示例推荐下拉框；WinOne 并非照搬该例，而是根据本项目用户明确认可的可见选择块，展示全部三个主题选项。Carbon/NN/g 的原则支撑控件选择与可识别性，不构成此方案优于所有其他方案的实证结论。
- 200% 文字放大检查同时覆盖标题栏与最后一个字段。设置标题栏的窗口操作保持 44 DIP 目标宽度，名称可省略但 Logo 不裁切；页尾预留滚动空间，让最后一个控件可滚到浮动滚页按钮上方。

### 不采用

- 不照搬 Liquid Glass、macOS 窗口按钮或平台快捷键；它们不是解决 WinOne 信息密度的前提。
- 不按 Apple“减少设置”的建议直接删选项。WinOne 保留已接入的全部能力，通过组织降低负担。
- 不用极浅文字、10–12px 小字、隐藏滚动溢出来伪造“干净”。
- 不把所有设置都做成卡片，也不把每行都做成可展开项。
- 不改变 Chat 的组件、样式、输入、滚动或导航行为。2026-10-17 起，AI 路由与插件按 WinOne 重新组织视觉，不再要求保留 Magpie 原版画面；完整能力、执行与安全边界不变。

## 3. 四层信息结构

| 层级 | 回答的问题 | 表达方式 |
| --- | --- | --- |
| 产品导航 | 我在配置哪个工具？ | 原侧栏，顺序和拖宽行为不变，不重复大页标题 |
| 页内任务 | 我想调整什么？ | 一级分段标签，二级下划线；每个一级 Tab 的图标和标题始终单行；空间充足时完整显示，窄窗可省略并提供完整标题提示与可访问名称 |
| 功能分组 | 哪些设置一起起作用？ | 17px 分组标题、清晰留白；必要时一句用途，默认不堆组说明 |
| 设置项与帮助 | 改什么、怎么改、有什么结果？ | 15px 字段名称和就近控件；14px 必要解释；可选细节使用描述性展开入口 |

- 导航之间最多两层；复杂业务已有的二级页保留，不为每个子分组再加标签。
- 字段的层级不能靠相同的 h3 不断堆叠。互斥选项的标签是字段名称，不是假分组标题。
- 分组用“外观”“保存位置”“运行限制”等任务或对象名称，不用“基础能力”“服务策略配置项”等内部表达。
- 一个组通常只解决一个问题。字段数量不是硬限制，关联强的字段不为凑数拆开。
- 明确依赖的选项放在父开关下方并缩进。切换父开关不能顺便清空用户已有参数。
- 普通开关默认保留既有保存机制，不把某些页偷偷改成自动保存。

## 4. 视觉令牌与布局

### 4.1 字体

| 用途 | 尺寸 / 行高 | 字重 |
| --- | --- | --- |
| 分组标题 | 17 / 25.5px（`1.0625rem`） | 600 |
| 字段名称与主要内容 | 15 / 24px | 400–500 |
| 帮助、状态与次要信息 | 14 / 22px | 400 |
| 标签与按钮 | 14 / 22px | 500 |

字号使用 rem，支持文字放大。列表和数据工作区不强行扩大所有控制；说明与正文允许换行，标题/导航名称先争取完整单行空间，不能因固定窄栏强制折行。程序管理的单行列表继续遵守原约定，完整名称以 title 和详情可达。

### 4.2 间距

- 基础步进 4px。标签到控件 8px；相关字段通常 16–24px；组标题到组内容 20px。
- 不同功能组相隔 40px（`--settings-group-gap: 2.5rem`）；组标题到组内容 24px（`--settings-heading-gap`）；相关字段 20px（`--settings-field-gap`）。组堆叠由明确的父容器控制；组自身不叠加相邻 margin/padding。
- 同一页内相邻的分组之间画一条细线（`--settings-hairline`，2dppx 下 0.5px）并加大间距：组间距 40px ＋ 细线下方 28px，合计约 68px；首个分组不画线。展开区内的相邻分组同样处理，不重复叠加第二条线。
- 页内导航到内容 24px；设置行最小 48px（`3rem`）；常规控件 36px（`2.25rem`），主要选择目标 40px（`2.5rem`）。
- 简单设置最大宽度 1088px（`max-width: 68rem`，含页边距），居中形成稳定阅读线。页边距宽窗 32px、窄面板 16px。程序/文件双栏等工作区允许更宽。页尾下内边距 2rem，最后一个字段滚到底时停在浮动滚页按钮上方；不再额外预留 5.5rem。
- 页边距随实际容器调整；窄区域优先减少页边距，再改列数，最后换行。绝不靠隐藏超出的控件解决溢出。
- 主布局以单列为主。只有数值对、时序对等紧密相关字段使用双列；按实际面板宽度重排，而非浏览器整体宽度。

### 4.3 色彩与形状

颜色分两层，规则不同：

- **界面层只用黑白灰。** 画布、表面、井、悬停、选中、正文、次要文字、边框、分隔线、焦点环全部取中性灰阶；选中态靠灰阶对比、线条、单选标记与文字表达，不用彩色填充，也不用大面积色块表示"当前页"。浅色主题实测：画布 `#fcfcfc`、表面 `#ffffff`、井 `#efefef`、悬停 `#e7e7e7`、正文 `#262626`、次要文字 `#636363`、强调 `#525252`、选中底 `#e9e9e9`、可编辑边界 `#7d7d7d`；深色主题同构（`#191919 / #232323 / #2b2b2b / #333333 / #e9e9e9 / #aeaeae / #c4c4c4 / #363636 / #7e7e7e`）。
- **数据与状态层保留原色。** 用量统计的分段与图表序列、模型"免费"标签、供应商与模型图标、程序列表图标、文件与目录链接的类型底色、错误与失败提示，都使用各自的既有配色；这些颜色承担区分与警示作用，不能为了"界面统一"被灰阶替换。
- 分组平面化，靠留白和一条必要分隔线组织；有独立交互边界的列表、弹层保留现有容器。结构线在 2dppx 屏幕上取 0.5px，输入框与未选控件的边界保持 1px 可辨识宽度。
- 不新增装饰阴影、悬停位移、纯视觉弹跳或背景模糊。尊重减少动效与强制颜色设置；强制颜色下选中与焦点改用系统 `Highlight`/`ButtonText`。

### 4.4 细节检查

- 先判断真实字段属于哪个任务，再选择分组。不能仅把全部内容加大间距，也不能靠堆相同卡片获得层级。
- 设置名称从同一左边线开始；同类控件从同一控制列开始。短表单限制阅读宽度，避免标签在最左、控件在窗口最右。窄面板改为标签在上、控件在下。
- 相邻功能组测量“上一组最后一个内容 → 下一组标题”，不能用父容器的 gap 数值替代可见结果。单个间距只保留一个控制点。
- Tab 的图标不压缩，标题不拆行；说明、错误或加载只改变所属面板，不改变上方导航坐标。指示线几何在所有状态下固定，选中变化只改变可见性/颜色；禁止退出选中后先跳位置再淡出，检查快速切换、嵌套、折行和减少动效。
- 名称、说明、状态各司其职。移除重复标签；错误说明原因与下一步，空状态给出入口；权限、费用和破坏性操作的后果仍直接可见。
- 在真实窗口比较默认、选中、禁用、键盘焦点、错误、草稿和保存后状态。截图用于自查，不能代替逐项操作与保存后重读。

### 4.5 一级标签、分组标题与控件形式

- **一级标签表达"当前在哪一页"**：图标 + 名称，选中态由 2px 下划线（贴在分隔线上）与更深的文字表达，不铺色块；未选中悬停给一层极浅灰底。二级标签（弹层内、审查面板内）只用下划线、不带图标，避免与一级混淆。
- **标签直接下属的分组标题统一带图标**，同一页不能一部分有、一部分没有；分组内部更小的小标题不带图标，保持层级差别。
- **形式按任务选**：短、少数互斥选项用紧凑分段；需要解释后果的选择用带说明的选择行；模型、路径、长目录保留下拉或列表；普通设置统一为"分组标题＋控制列"。同类任务在不同页面必须用同一种形式。
- **一个任务只有一个动作入口**：分区标题写任务名，动作按钮写下一步动作，不重复同一句话（例如标题"导出配置"配按钮"导出到文件"）。动作与结果同排，不再把按钮堆在整段说明文字之上。
- **禁止无谓挤压**：有可用宽度时，名称、标签与列名不得换行或被截断；导航/动作包左栏按最长名称＋图标＋折叠箭头＋内边距自适应，不用固定 14/15rem 上限阻止扩宽。右侧有空间必须让出空间；确实不足时按实际容器重排，极长自定义名称才单行省略，并保留完整标题提示和可访问名称。绝不以缩小字号、提前省略或换行掩盖分栏分配不合理。

## 5. 文案与交互

### 标签与帮助

1. 先尝试只写清楚的设置名称。需要解释时，只说作用或必要条件。
2. 一条说明只表达一个意思，不重复标题，不重复按钮，不同时解释“开”和“关”。
3. 路径、ID、完整协议名在需要复制/诊断的地方显示；不代替面向用户的名称。
4. 同列反复出现的“位置”“显示”“触发手势”可提升为列表列名；每个控件的可访问名称仍保留。
5. 补充帮助的入口应写“支持的接口”“快捷助手功能说明”，不是孤立的问号或“更多”。只读帮助不替代操作入口。
6. 错误、收费/额度影响、权限授权、删除后果、配置冲突以及当前未保存状态必须直接可见。

### 保存与反馈

- 同一草稿跨标签、帮助展开和分组切换保留。不要为排版改变配置字段、提交载荷或并发版本校验。
- 独立事务（例如快捷键与截图参数）保留独立且明确命名的保存按钮，不做一个假“保存全部”。
- 全局设置页内切换不放弃草稿；离开整个页面仍使用原有未保存保护。
- 修改中的禁用控制需要明确原因，不能点击后毫无反应。日志入口不受其他设置读取失败影响。
- 异步反馈放在所属内容区域，不插入导航上方，避免切换时标签坐标跳动。
- 快捷键是所属模块自己的一个标签页，不插在页面顶部；草稿随标签切换保留，录入、冲突提示与保存语义不变。
- 失败恢复实际状态；保留原原因和下一步，不用更“漂亮”的提示掩盖失败。

## 7. 验收契约

### 可重复检查

- 正常/加载/空/失败/保存中/未保存；父选项开关前后；帮助展开前后；标签切换前后。
- 中文、英文 × 浅色、深色 × 窄窗/中窗/宽窗；实际侧栏与双栏拖宽；长路径、长名称、多模型。
- 125% / 150% / 200% 文字缩放；控件不重叠，设置名称不裁掉，底部操作可滚达，无横向滚动条；一级 Tab 仅在空间不足时按上述规则省略。
- 标签切换前后比较导航的 x/y 坐标；每个一级 Tab 的标题实测为单行，宽窗完整、窄窗省略时全名仍可达，不缩小字号；帮助只能推开所属内容，不能把全局导航顶走。
- 真实点击、键盘 Tab/Enter/方向键、字段修改、跨标签保留、保存载荷与错误保护。不只做 CSS 溢出检查。
- 所有代表页面及每种主布局至少查看实际截图；浏览器夹具只能证明界面行为，不能声称真实 UAC、文件链接或账号请求通过。
- 检查 Chat 原有文件未增加本轮改动；运行其现有回归，并核对 `.settings-surface` 不出现在 Chat。
- 颜色契约由计算样式断言，而不是读源码：界面令牌必须为纯灰阶，`--destructive` 必须保留语义色，选中标签的背景必须透明且下划线可见。
- 使用场景等导航栏的名称必须单行渲染；宽度足够时换行即判失败。

### 用户体验复核

让用户从未见过的新版本完成：修改截图保存目录、调整快捷助手功能顺序、设一个程序定时退出、找到网关地址/密钥、查找启动失败日志。记录首次找到入口的路径、误操作和需要帮助的位置。未做真实新用户观察时，只能称为设计准则与启发式/行为验证，不宣称用户完成速度已提高某个百分比。

实施进度、实际验证数量、输出位置及未覆盖内容写入 [开发状态](development.md)，不在本设计语言里虚列“已完成”。
