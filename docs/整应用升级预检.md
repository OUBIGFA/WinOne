# 整应用升级配置预检

2026-10-08。安装器在覆盖程序文件前，用暂存的新 Host 检查已有配置。覆盖后仍执行完整的 Host、Worker 和界面启动检查。

## 检查范围

- 无扩展数据时继续使用原 `--check-configuration` 协议，保持旧版回滚兼容。
- 有扩展数据时使用 `--check-profile <nonce> --profile-root <绝对目录>`。配置字节通过标准输入传入；不通过命令行传递配置或密钥。
- 配置、模块启停状态、包登记和回收记录共同形成摘要。回应绑定实际进程、映像路径、随机标识和配置摘要；调用前后再次读取控制文件，变化则拒绝。
- 使用目标 Host 的信任根和兼容策略校验已登记包。检查不创建运行时 Gate、不启动扩展、不写配置投影，也不执行配置迁移。
- 尚未完成的配置事务、包变更或资源恢复会阻止覆盖。有效但不兼容的模块会在覆盖前指出。
- 既有缺失、损坏、不受信任或配置错误的扩展沿用正常 Host 的隔离策略；保留原数据，并在检查报告中列明。不是静默接受模块，也不会执行它。

报告保存到升级工作目录的 `profile-check.json`，只包含模块标识及固定原因，不包含配置值。界面继续由正常 Host 的工具管理页显示隔离状态。报告最多列出 32 项，另有总数。

## 失败与重试

安装事务按“校验旧包 → 新 Host 配置预检 → 恢复托管资源 → 覆盖 → 完整启动检查”执行。预检失败时保留 `prepared` 阶段；只有确认旧包、登记和快捷方式完整，并核对标记属于本次操作，才清除残留阻止启动标记。用户可运行旧版完成恢复，再重试安装。

覆盖后的实际启动失败仍使用原有回滚流程，不用预检替代 Worker 或界面验收。

## 实现与验证入口

- `internal/startupprobe/profile.go`：有界只读快照及摘要。
- `apps/host/profile_probe_windows.go`：目标 Host 的包验证、兼容和隔离判断。
- `internal/distribution/startup_windows.go`：安装器调用和检查报告。
- `internal/distribution/execution_windows.go`：覆盖前顺序与失败保护。
- `TestNativeProfileProbeChecksPackagesDuringMaintenance`：真实 Host 的签名包检查及无副作用。
- `TestInstallerProfilePreflightStopsBeforeReplacementAndCanRetry`：真实 Host 预检接入受控安装事务。
- `TestNativeInstallerSameVersionOverwrite`：完整 NSIS 覆盖、重复覆盖、启动失败回滚及卸载。显式设置 `WINONE_INSTALLER_PROFILE_FIXTURE` 时，增加待恢复状态拒绝、解除后重试和隔离配置保留验证；测试用发布者不加入正式信任根。
