# 统一体验与设计依据

更新：2026-09-29。用于 WinOne 的产品设计与验收；组件网站和设计文章不是 WinOne 已通过验证的证据。

## 1. 已核实依据与项目决策

| 依据 | 来源结论 | WinOne 的落实方式 |
| --- | --- | --- |
| NN/g：渐进呈现 [S1] | 常用内容优先，低频/高级功能按需进入第二层；入口名称要明确 | 主页面提供常用操作；定时、频次、权限和排除等进入二级设置 |
| NN/g：识别优于回忆 [S2] | 有上下文的可见选择比要求用户自行回忆更容易使用 | 图标配文字；程序列表有名称和状态；快捷键可录入、可查看，不要求记住命令 |
| Microsoft：Windows 导航 [S3] | 一致、简洁、清晰；避免过深层级；列表/详情适合条目管理 | 固定产品导航；WinTray 使用列表→程序详情；返回路径保持清楚 |
| W3C：WCAG 2.2 [S4] | 对比度、键盘、焦点、目标尺寸与拖动替代操作均有要求 | 按 AA 检查；排序同时提供按钮；不只依赖颜色或鼠标悬停 |
| Base UI：可访问性 [S5] | 提供键盘和焦点等基础能力，标签、视觉焦点和对比度仍由应用负责 | 复用基础组件，同时测试 WinOne 的完整标签、焦点和交互 |
| WebView2 进程模型 [S8] | 一个界面环境可能包含浏览器、多个渲染及 GPU 等进程 | 统计完整进程组；共用配置一致的 UI 环境；关闭界面释放控制器 |

上述是资料支持的原则。导航项目、初始尺寸、资源预算和功能排序属于 WinOne 的设计决定，必须经原型、测试和实际用户任务修正。

## 3. 统一交互规则

- 一个页面只有一个主要任务区域，主操作明确；不把诊断、设置和操作混成一长列。
- 常用按钮使用图标加短文字。工具栏中只用图标的按钮必须有可访问名称、提示和快捷键说明。
- 简单开关直接应用；耗时显示处理中，失败恢复实际状态。多字段表单明确保存/取消。
- 已关闭模块展示状态、用途和“开启”入口，不展示整页无法操作的控件。
- 导入先展示差异；缺失程序提供“选择位置”，缺失模块提供“查看模块”。
- 错误先说明失败动作和可执行的下一步；技术错误码、堆栈与恢复账本放详情。
- 危险或不可逆动作使用明确动作名称，不能只写“确定”。
- 文案不解释内部实现，不重复提醒，不用“成功”掩盖部分完成。

这些规则采用 [S1–S5] 的原则，具体交互仍需在 WinOne 中检查。

## 4. 页面分层

### 首页

直接进入常用工具；显示少量真正需要处理的事项。模块运行统计、诊断和日志不占据首屏。新增模块默认在模块中心，用户可以固定入口。

### 截图

第一层：区域截图、最近截图、复制/保存/贴图、截图快捷键。

第二层：窗口/全屏/滚动方式、输出目录、捕获后行为、滚动选项。工具栏保留选区与常用标注，更多工具有明确入口。

编辑器：画布为主体；撤销/重做和复制/保存持续可见；选中对象后显示相关属性，不一次铺开所有工具参数。

滚动截图：选择目标 → 捕获中 → 停止 → 预览 → 使用结果。取消重选时保留旧结果，并明确说明预览属于哪次捕获。

贴图：右键打开菜单，Esc 关闭；复制、另存和恢复放在第一层，缩放与外观放在二级菜单。采用 Windows 上下文菜单习惯 [S21]，保留滚轮缩放和拖动。

### 窗口置顶

第一层：启用状态、快捷键、已置顶窗口、取消操作。

第二层：边框与颜色、排除程序、管理员模式。权限提升要说明影响，正常使用不强制管理员常驻。

### 启动与托盘

第一层：程序列表、添加程序、是否启用、常用启动方式与实际状态。

单程序二级页：参数、工作目录、托盘行为、等待时间、定时、运行频次、原自启接管。恢复记录和高级诊断继续位于同一二级页的明确分区，不隐藏功能。

模块设置二级页：登录行为、完成后退出、导入旧 WinTray。所有能力都通过 WinOne 完成。

### 模块与设置

模块页管理安装和开启状态；卸载、版本与依赖在详情。设置页集中外观、语言、配置迁移；更新与诊断进入二级页。

## 5. 视觉系统

保留 Cindy 的克制、近单色和清晰层次方向，使用统一令牌定义颜色、字体、间距、圆角、焦点、图标尺寸与动效。

- 平面分区优先，少用卡片和阴影；不做卡片套卡片。
- 正文优先 14–16 DIP，标题用 medium/semibold；辅助文字仍须可读。
- 控件触达区域按场景设计；满足 WCAG 2.2 的目标尺寸要求及其适用例外，不把图标像素尺寸当作点击面积。
- 浅色、深色、高对比度、125%/150%/200% 缩放均检查；不只制作一张静态浅色图。
- 所有资源本地加载；主题切换、错误状态和空状态使用同一套组件。
- 动效短且有功能目的，尊重减少动画设置。

这些数值是原型起点，不作为普适心理学结论宣传。

## 6. 验收方法

先评审代表页面，再推广到全部模块。每轮邀请真实新用户完成代表任务，记录首次完成、错误、求助和返回路径；不以开发者自己会操作替代用户验证。

代表任务：完成一次截图并复制、取消一个置顶、添加一个登录启动程序、将配置导入另一台设备、安装并关闭一个扩展。

需要确认：用户是否知道下一步、是否能找到高级设置、是否理解模块关闭与卸载的区别、是否能处理路径/快捷键冲突。没有实际用户观察记录时只能称为启发式评审通过。
