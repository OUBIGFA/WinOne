# 截图单界面重构

状态：2026-10-02，普通截图已切换为原生画布和工具栏，测试包已更新，用户实机体验尚待验收。当前实现状态以 [开发状态](development.md) 为准；下文包含历史路线与验证记录。

当前设置页保留 React/shadcn；普通截图在同一原生窗口内完成选区、标注、文字、输出和取消。原生草稿支持恢复可编辑图层与未提交文字。重复快捷键唤回当前截图，不排队创建新截图。滚动截图仍使用既有采集与后续编辑路径，必须继续完成统一，不能将普通截图的验证视为全部截图功能完成。

## 操作约定

- 截图从选区到标注使用同一窗口、同一画布；确定选区只显示工具栏，不重建窗口、不更换背景。
- 默认选窗；窗口边缘选整窗，内部识别区域；左键拖动自由框选。
- 待选、单击未拖动和确认选区后显示普通指针；拖动框选时显示十字准星。文字输入、缩放握柄及移动操作保留对应指针。
- 选定后可直接调整四边、四角、移动选区、连续标注和输入文字。
- 箭头、形状、画笔和文字使用平面样式，新标注不添加阴影。
- 左键双击确认、复制并退出；不隐式写入文件。保存与另存为使用对应按钮。
- 右键单击取消本次截图；不弹确认框。工具栏菜单按正常菜单交互，不能把菜单内部点击误当截图动作。
- “截图后编辑”默认第一项；明确选择“截完保存”时选区完成后直接保存。
- 复制、保存失败保留截图和标注，提示可重试；不能提前退出。

### 滚动停止面板（接入中）

- 滚动期间显示“停止”和 Esc 提示；停止后检查已捕获内容，取消或失败后释放面板。
- 操作面板不抢走目标窗口焦点，不进入截图；不能满足时停止启动并提示原因。
- 原生重截和正式入口尚未接通，真实屏幕排除与 Esc 输入效果待验证。

依据：[微软 SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity) 将录制控制窗口排除作为用途，`WDA_EXCLUDEFROMCAPTURE` 从 Windows 10 2004 起支持，依赖桌面合成；[WS_EX_NOACTIVATE](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles) 避免点击窗口夺取前台；[WM_MOUSEACTIVATE](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-mouseactivate) 的 `MA_NOACTIVATE` 保留鼠标消息。以上只说明接口适用范围，不替代 WinOne 的真实截图验证。

## 成熟实现对照与决定

| 参考 | 已核对的事实 | WinOne 的采用范围 |

## 替换后的职责

- **设置窗口**只负责 WinOne 设置、配置和发起命令，不再挂载截图画布，不变成全屏截图窗口。
- **截图窗口**使用独立窗口身份和前端入口；准备图像、尺寸与首帧后出现。选区、调整、标注、工具栏、输出都属于这一个窗口。
- 截图窗口没有首页、侧栏、普通标题栏、设置页初始化或任务栏缩放过程；失败界面也不临时变成设置页。
- 确认或取消后直接结束截图窗口，不执行“还原成设置窗口”的流程。已打开的设置窗口保持自身尺寸、草稿和可见性。
- 快捷键与设置页按钮汇入相同入口。重复发起只唤醒正在进行的截图，不并行创建两个编辑会话。
- WinOne 统一配置和 UI 不变；窗口职责分开不等于保留上游独立产品界面。

## 实施路线

1. **独立入口与窗口身份**：分离设置/截图前端入口、单实例标识、窗口类与启动配置。验证两个窗口并存且互不改变尺寸及页面；截图入口不得加载 AppShell。
2. **替换完整生命周期**：所有截图入口转发到截图窗口；移走设置页里的截图接收器与画布。接入准备、显示、选区、标注、完成、失败与取消的完整状态转换，删除截图窗口中的设置恢复路径。
3. **连续任务验收后切换测试包**：覆盖呼出→选区→标注→双击确认、呼出→右键取消、保存失败重试、再次截图、重截、重启恢复。比较成熟产品和 WinOne 的真实连续操作；未通过不交付，也不再用“某个节点没有重建”代替体验结论。

独立前端入口已建立：`capture.html`、`src/capture-main.tsx`、`src/capture-app.tsx`。只装载截图工作区，准备期间不挂载设置页，失败显示可关闭的截图错误页，完成时保留最后画面直到窗口销毁。两项入口回归、类型检查和双入口前端构建通过。原生截图窗口已接入独立单实例标识、窗口类、缓存目录及页面映射；结束只隐藏并关闭，不恢复设置窗口。设置窗口不再自动接管磁盘中的截图草稿。原生角色、页面映射及恢复范围回归通过。设置页按钮已转发到 Host 统一窗口管理器，设置页中的截图接收器和画布已移除。重复请求复用正在运行的截图窗口，设置页等待真实进程退出后才恢复。原生、前端回归与完整构建通过；当前仍为内部验证包。

## 验收边界

正式接入先复用现有输出服务：原生UI提供最终位图，保存、另存为、命名、防覆盖和复制由同一截图模块处理；编辑会话固定自己的配置快照。原型已验证该输出边界，真实采集与Host调度接入仍未完成。

- 拖动握柄位于整个工具栏最左侧、两行总高度的垂直中心，提供明确拖动提示与足够命中区域。优先保留标准原生控件；凸出造型影响原生控件时不采用。

- 实际截图过程中窗口身份保持不变，选区完成不发生隐藏/重开；画面与工具栏无空白帧、闪屏。
- 双击只执行一次确认；不得额外画出标注或触发第二次复制。
- 右键取消不产生文件、不改变剪贴板、不遗留草稿与遮罩。
- 未确定选区不能导出整屏；截图失败保留有效选区及已有编辑。
- 文字输入、连续马赛克、窗口内部识别、两行工具栏和拖动手柄全部保留。
- 覆盖中英、混合DPI、负坐标、长截图、首次冷启动与再次截图；验证完整进程组退出与回收。
- 隔离桌面与浏览器回归用于定位问题；实际桌面录屏和完整操作未验证时，不宣称“无闪屏”或完成体验验收。

## 承载性能门槛复核

预置图片测试显示全WebView截图窗口再次出现的中位耗时855ms，首次新配置1278ms，尚未加上真实截屏开销；当前路线不得继续包装成交付版。详见[资源基线](performance-baseline.md)。

保留设置与截图职责分离的设计。下一轮先验证成熟原生画布承载与WinOne统一工具栏能否完成同一个截图会话：原位选区、连续标注、原位文字、双击确认、右键取消和失败重试都必须一起成立。不得用上游另一套设置/编辑界面替代统一UI，也不得用常驻隐藏浏览器或放宽指标掩盖每次启动的成本。原生参考样本未包含统一配置、通信与输入就绪，不能直接用于产品验收。

## 原生承载可行性检查

ShareX 21.0.0 的默认文字工具通过 `TextDrawingInputBox.ShowDialogTopMost` 输入，并支持多个区域；不能因其显示较快就直接作为 WinOne 的最终交互。Flameshot v14.0.0（提交 `e408812d77ff1835957f85796c4cf737466bd69d`）的 `TextTool::widget`、`REQ_ADD_CHILD_WIDGET` 和 `SelectionWidget` 分别提供画布内文字与单选区交互，作为契合度对照；右键取色等行为不照搬。

原型位于 `tests/capture-host-probe/`，目前只完成原生适配边界：在独立 ShareX 副本中编译同程序集适配层，复用原生绘制、输出和历史，不改写产品依赖源码。已验证矩形生成实际像素、撤销还原原图、重做像素一致；没有显示用户窗口。

WebView2 SDK 1.0.4258.31 已锁定为测试依赖，并保留许可。同窗口工具栏向原生引擎发命令，浏览器不接管图像画布。单选区策略、完整快捷操作、窗口出现和可操作耗时仍未通过，原型不能进入发布包。

### 同窗口控件联动结果

原型现已嵌入项目现有 shadcn/ui 控件。预置选区和矩形后，实际点击撤销、重做、保存、切换模糊工具及取消均成功；通过实时 HWND 和 GetAncestor 确认工具栏属于原始图像窗口。浏览器没有 canvas/img 图像层，多轮输出均为700×400且像素摘要相同。证据：`_temp/native-capture-host-probe-1002/live-parent-check/output/verification.json`。这些检查不覆盖真实鼠标绘制及文字输入。

分段计时表明隐藏初始化存在节流成本。同版控件、同隔离缓存下，隐藏组工具栏约1661ms就绪，可见但不可操作的诊断组约736ms，另一轮约754ms；均从托管入口计时，不含完整进程启动与实际采集。参考 [WebView2 IsVisible](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2controller.isvisible) 的隐藏节流说明。诊断组不构成产品呈现决策：透明显示、初始输入行为、完整冷/热耗时和原位文字仍须一起验证。

### 原位文字阶段

原型已复用现有画布文字输入组件，在同一窗口内输入多行中文并提交给原生历史。实际控件测试覆盖取消不新增标注、直接点击保存先提交文字、一次撤销移除文字、重做还原相同输出。窗口数始终为1，实时 HWND 不变；通过 GetWindowRgn/PtInRegion 检查工具栏和文字区有效，而中间画布不属于浏览器区域。证据：`_temp/native-capture-host-probe-1002/live-text-region/output/text-verification.json`。

这是预设位置的原型验证，不代表真实鼠标定位、再次编辑、输入法组合与多DPI流程通过。输入截图与输出按颜色阈值提取的字形边界仍有约1–2像素差异，说明双文本渲染路径还需评估；不添加样本偏移补偿，不据此宣称完整所见即所得。

已补齐当前选中文字的再次编辑原型：保留原图层与位置，取消恢复原内容，修改提交仅产生一步原生历史。真实控件测试和PNG像素对照通过；清空及撤销恢复自测通过。记录：`_temp/native-capture-host-probe-1002/live-text-edit/output/`。鼠标点击定位与选择、真实IME、字形显示一致性仍未通过验收，不进入产品。

文字工具已取消固定落点：先选工具，再根据原生WM_LBUTTONDOWN的有符号客户区坐标创建或命中文字。选区外及不足以输入的位置明确拒绝。定向消息验证坐标保持、命中重编辑、新增第二段文字；既有文字保存/取消回归也已迁移并通过。记录：`_temp/native-capture-host-probe-1002/live-text-point-bounds/`、`live-point-text-regression/`、`live-point-edit-regression/`。这些测试仅操作经身份校验的隔离窗口，不代表硬件鼠标、IME或视觉连续性通过。

### 确认与取消阶段

同一确认事务处理原生双击消息和工具栏确认：输出失败保留截图，成功后退出，重复请求不再次复制。文字先提交再确认，空白文字也继续确认；右键取消不生成输出。四场隔离回归及原生自测通过，证据为 `_temp/native-capture-host-probe-1002/confirm-green-*/output/confirmation-verification.json`。空白文字曾导致确认丢失，已有先失败后通过的回归证据。

测试使用定向消息和PNG接收器，不操作系统剪贴板；不代表完整双击鼠标序列或实际桌面体验通过。跨私有桌面复用WebView缓存、调试端口曾分别导致资源占用和连接失败，已通过按场隔离测试资源解决，未向产品加入延时或重试。

### 单选区与历史范围

后续切换顺序：

1. 保存并校验原生选区、图层和文字实际排版，往返恢复后输出像素一致；拒绝未知图层类型、异常坐标及越界选区。
2. 接入 Worker 恢复与 Host 路由，保留旧草稿可恢复能力，普通截图完成不再创建网页编辑窗口。
3. 接入滚动结果编辑、重截与完整重启恢复，再执行安装包、进程组性能和连续画面验收。
