# 鼠标手势场景配置验收

本次将鼠标手势保留在“便捷功能”内，首页不再重复列出独立模块项。设置默认打开“使用场景”，资源管理器排第一。宽窗口使用场景列表，窄窗口使用完整场景下拉菜单；每个场景直接显示轨迹、动作、手势分配及动作启停。

## 行为与配置保护

- 场景排序只改变显示，不重排用户保存或导入的范围规则。
- 场景编辑复用既有 `actionPackages` / `scopes` 格式。首次修改共享动作包时创建当前场景专用包，仅替换当前场景的引用；原包、全部脚本及其他场景保持不变。新包 ID 和名称唯一。
- 新增动作保留所选动作的完整 C# 源码，也可直接编写自定义脚本。已有包顺序与“后包优先、包内第一个已启用动作优先”语义不变；被覆盖的动作仍显示，并注明实际优先动作。
- 复制、删除、编辑、还原及保存沿用未保存保护。32 个动作包的既有格式上限没有改变；达到上限时明确提示，不丢弃其他设置。
- “场景设置”保留完整路径、每行正则、窗口类名、关联动作包、窗口列表和准星选取。所有场景都保留独立启停。
- 编译、排除、线程、动作树和手势库仍可直接打开。保存反馈移到标签组下方，切换与保存不推动标签导航。
- 全局配置导入导出继续由 `internal/profiles/stroke.go` 处理。其 `stroke.Preferences` 完整保留动作包、脚本及范围引用；程序和 DLL 路径继续使用本机映射，本次没有增加配置字段。

## 验证

1. `npm test -- src/features/mouse-gestures.test.tsx src/features/mouse-gestures-scenes-model.test.ts src/features/modules.test.tsx --pool=threads --maxWorkers=1 --reporter=dot`：3 个文件、30 项通过。
2. `build/build-stroke.ps1 -OutputDirectory _temp/20261011-experience-gestures/worker -Test`：原生行为套件通过，覆盖轨迹向量、16 按键组合、特殊手势、范围先行、Explorer 身份、普通点击恢复、取消、x64 INPUT/DPI、GDI 释放及自有输入回收。
3. `build/test-mouse-gestures.ps1`：新增统一入口，使用候选 Worker、现有 Playwright 和已有 Chromium；工具路径通过参数提供。中英、深浅、520/1000 px 共 8 组通过。验证场景独立分配、保存后重开、31 个原始动作、默认仅 Explorer、显式启用浏览器、录制保存、标签坐标不变及无横向溢出。
4. 已实际查看宽、窄窗口截图。首次截图显示窄窗场景列表挤占首屏，改为成熟 Select 后，首屏可见手势与对应动作。

过程证据位于 `_temp/20261011-experience-gestures/`，最终浏览器报告为 `browser-2/layout/report.json`。测试入口负责回收自身 Vite，浏览器驱动负责关闭自身 Worker 和无头浏览器；没有启动真实 WinOne 安装或修改真实配置。

首轮浏览器检查中途出现关闭管道诊断；保留失败记录并修正 PowerShell 对原生 stderr 的截断，随后完整 8 组通过。没有放宽 Worker 超时或更改正式执行行为。

本次浏览器使用隔离 `--fixture`，不安装全局鼠标钩子。物理鼠标操作真实资源管理器、提权窗口、真实用户键盘钩子、多显示器轨迹以及完整 WinOne 进程组性能不属于本次已验证范围。正式安装器、真实安装和用户配置均未修改。
