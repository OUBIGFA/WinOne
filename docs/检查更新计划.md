# 检查更新

状态：实施中。属于架构计划P4，不替代现有截图、托盘和资源验收。

## 当前与后两步

1. 手动检查：从构建指定的公开GitHub仓库读取最新正式版本；版本比较复用现有SemVer实现。区分未配置、检查中、有更新、无更新、未找到可用发行版本、网络失败和限流；失败不得显示“已是最新版”。只在用户检查时联网，无后台轮询。先完成协议及隔离测试，再接全局设置界面。
2. 产品入口：全局设置显示当前版本、检查按钮、最新版本与发行说明入口。中英双语、键盘、窄屏、取消及重复点击进入回归。真实发布仓库尚未确定；未配置时不向示例仓库发请求，不宣称已经提供可用的在线更新。
3. 应用升级：复用`internal/distribution`的校验、维护锁、准备、切换与恢复。正式下载/执行需补齐发布者验证及可信发布配置；之后才接可选模块包。当前手动检查不下载、安装或运行代码。

## 边界与验收

- 只读取最新非草稿、非预发布版本；API错误、畸形数据、超大响应、重复JSON字段和无效版本均报检查失败。
- 请求有超时、取消和响应大小限制；不携带用户配置、账号凭据或遥测。发行页面地址由固定仓库和已验证标签组成，不打开响应中的任意地址。
- 正式版本通过HTTPS读取；测试使用替代HTTP传输，不放开产品地址约束。发行说明按外部文本处理，不作为指令或脚本。
- 手动检查只证明指定仓库发布了相应版本，不证明安装包发布者身份。不得把SHA-256或版本比较当作代码签名。
- 验收覆盖新/同/旧版本、预发布、空发布、离线、限流、超时、取消、重定向、格式错误与超大响应；界面与真实发行源分别标记验证状态。

## 已核对依据（2026-10-02）

- [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)：latest排除草稿及预发布；“latest”由平台发布规则决定，不自行猜测发布日期与版本顺序。
- [PowerToys UpdateUtils](https://github.com/microsoft/PowerToys/blob/main/src/runner/UpdateUtils.cpp)：检查结果、可下载版本及安装状态分开处理；本项目复用自己的安装恢复实现。
- [TUF规范](https://theupdateframework.github.io/specification/latest/)：后续可信更新的角色、签名、过期和版本回退约束。当前GitHub手动检查不宣称具备TUF的完整保障。

发布源和代码签名身份仍待实际发布阶段落实；本计划不授权对外建仓或发布。

## 构建与入口

统一构建支持 `-UpdateRepository owner/repository`。省略时关闭在线检查；禁止URL、空白或额外路径。版本从前端包版本注入桌面程序，普通开发构建使用同一包版本作为后备。仓库参数不存入可导入配置。

全局设置的“更新”显示版本和检查按钮。网络检查可取消；离开设置页和关闭窗口会取消本次请求。重复请求不能并行，过期取消不能停止后来请求；失败清除旧发行链接。发行说明只使用原生端保存的成功检查结果打开。

原生会话/参数注入、UI取消/重试/离开保护和16个中英文800/520像素状态场景已验证。浏览器测试使用内存检查结果，不请求真实GitHub发行源；脚本：`tests/updates-check.mjs`。正式源尚未指定，当前构建不向示例仓库联网。
