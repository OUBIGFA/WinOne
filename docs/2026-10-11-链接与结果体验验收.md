## “已复制”截断的根因与结果

旧标题栏固定给左右各 60 DIP。左侧置顶按钮和间距占用 32 DIP，状态文字只剩 28 DIP；中文“已复制”的实际测量宽度为 42 DIP。因此扩大窗口也无法解决。

现实现按 MyGo 当前字体及文字缩放测量状态宽度，为两侧分配相同空间。保留既有“拖动图标与标题整组居中”行为，置顶和关闭按钮不移动。空间确实不足的长状态仍可省略，并保留完整提示；短状态在可用空间足够时完整显示。

`TestShortHeaderNoticesHaveTheirMeasuredWidth` 检查三种结果来源、中英文、深浅主题、320/520/900 DIP 和 100%/150% 文字缩放，覆盖“已复制 / 已停止 / 收到新回复”共 216 个状态组合；始终检查操作按钮可达且状态不覆盖拖动区。结果 UI 全包测试通过。截图已人工核对修改前的“已…”与修改后的完整“已复制”。

原生模型选择的既有免费标签测试也通过。本轮之后追加的倍率和长上下文标签由主任务继续接入，不将本次“免费”检查当作其他标签已完成的证据。

## 真实拖放发现并修复的宿主问题

首次真实 OLE 测试中，来源窗完成了 7 步鼠标移动并在目标释放，但 Windows 返回 `DROPEFFECT_NONE`，界面没有收到路径。Wry 0.57.0 在此路径只调用 `CoInitializeEx`，随后忽略 `RegisterDragDrop` 的失败结果；WinOne 自建 Win32 宿主没有执行额外的 OLE 初始化。

[微软 RegisterDragDrop 文档](https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-registerdragdrop)明确说明：只用 `CoInitialize` / `CoInitializeEx` 而没有 `OleInitialize` 时，该注册始终返回 `E_OUTOFMEMORY`。

`component_ui.rs` 现在在创建 WebView 前建立仅属于 UI 线程的 OLE 生命周期对象。初始化失败返回带 HRESULT 的明确错误；所有 WebView 释放后配对 `OleUninitialize`。未改动 Wry 源码或以浏览器事件伪造补偿。只增加现有 `windows-sys` 版本的 `Win32_System_Ole` feature，没有新增运行时安装。

仅改变这项初始化后，用同一 WinForms `DataObject(FileDrop)` / `DoDragDrop` 来源探针复验，五次真实跨进程拖放全部通过。最终截图已人工核对左侧拖入来源、右侧现有内容与冲突。`ole-check-2/result.json` 保存每次来源/目标 PID、动作轨迹和实际界面结果；结束后再次核对本任务进程数为 0。

- 当前普通 Windows 令牌不能创建文件或目录符号链接，错误为 1314。补验需要已获准的提升令牌或机器既有开发者模式；本轮没有更改系统模式，也没有把权限失败标成成功。
