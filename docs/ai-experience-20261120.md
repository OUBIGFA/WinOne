本次解决已配置供应商的模型管理被低频参数阻隔、启停占据整块空间，以及预设/批量选择/参数页间距、圆角、对齐不一致的问题。保持四个一级入口、原配置字段、全部服务能力和保存事务，使用现有 MyGo 原生组件。未升级 AI 基座或 UI 依赖。

## 设计依据

- [Impeccable 4.10.0](https://github.com/pbakaus/impeccable/tree/b49177d32788f2dc585c42831d845dacf1ebed2c)，Apache-2.0。使用 Operate、distill、polish、clarify、onboard、craft-floor 方法；原生 audit 的平台无关检查用于辅助，未将 iOS/Android 检查分数套在 Windows 上。只读取方法，无第三方脚本执行、全局安装、代码/素材复制或截图上传。
- [NN/g：Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)：日常任务优先，按需显示高级及低频配置，功能不因精简而丢失。
- [NN/g：10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)：一致性、识别优先、可见状态、错误恢复与用户控制。
- [Microsoft：App settings guidelines](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)：频繁操作不埋入设置页，相关设置分组，使用统一行/展开组件，并限制宽屏阅读宽度。

上述资料在本次直接读取核对。Impeccable 自动上下文加载器和网页 DOM 检测器未运行；验收依据是生产组件测试与 Windows 原生窗口。
