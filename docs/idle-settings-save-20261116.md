# 设置页面闲置后的保存冲突（2026-11-16）

## 根因与行为

AI 供应商的自动模型刷新复用配置存储，每次成功刷新，以及首次记录刷新错误，都会推进 AI 配置修订号。设置页只保留打开或上次保存时的修订号，随后整页保存被 `ErrConflict` 拒绝；重复保存仍使用同一旧值，因此无法恢复。

其他设置由统一配置文档管理。旧实现要求每个模块的保存都匹配整份文档的最新修订号，即使只有无关模块发生变化，也会拒绝仍然有效的草稿。

本次修复：

- AI 服务和截图的识别/翻译设置随保存发送最初读取的 `base`。后台持有原有写锁，比较原配置、草稿与当前配置，仅合并独立变化；没有 `base` 的旧调用继续执行严格修订校验。
- 后台模型报告先通过现有 `Provider.RefreshModels` 规则更新编辑基线，保留用户模型名称、手动模型、明确覆盖及取消勾选。闲置时下架的模型可进入暂停列表；删除供应商不会仅因其后台刷新而失败。用户手动获取的较新列表和成功后清除的错误状态保留，后台的旧失败不能恢复到草稿。
- JSON 合并按字段和记录 ID 对齐，不按数组位置替换供应商或密钥槽。同一字段的不同修改、删除与编辑冲突在写入前返回；保留页面草稿与新密钥。错误只包含字段路径，不包含字段值。
- 统一配置存储记录每个模块最近一次已提交变化；截图、划词、快捷助手、置顶、鼠标手势、定时关机、程序管理和全局设置不再因其他模块的保存过期。读取、校验和提交使用同一写入锁，并发的独立保存不会互相丢失。此记录没有时间或历史数量过期策略，也不新增磁盘配置格式。
- 整份档案导入、模块安装/删除及恢复继续保留原有事务和冲突保护。失败事务的回滚不会推进编辑基线。
- Host 通道支持 4 MiB 消息，以容纳两份有独立大小限制的 AI 配置及请求封装。旧 Worker 默认帧限制和档案预览分块阈值仍为 1 MiB，AI 配置本身的上限不变。

## 验证方法

正式回归位于 `internal/configuration/idle_edit_test.go`、`internal/ai/configuration_*edit_windows_test.go`、`internal/ai/configuration_merge_windows_test.go`、`internal/configjson/merge_test.go`、`apps/host/idle_settings_windows_test.go` 与 `apps/desktop-mygo/pages/aiservices/idle_save_test.go`。协议和真实命名管道用例检查两份大配置能完整往返，并继续拒绝超限帧。

用 Git 原始文件生成只用于 Go 编译的 overlay，未替换工作区文件。旧版页面在后台刷新后保存失败；旧版模块在其他模块保存后失败，以及经过 40 次其他模块保存后失败。对应旧版输出保存在本次 `before-fix/`。修复后的用例核对真实存储、重新打开后的值、原生页面保存按钮及紧接着的第二次保存。

运行目录：`_temp/idle-settings-20261115/`。所有配置和测试资料均隔离在仓库内。连续 24 次刷新及模拟的报告时间用于确定性检查，不冒充真实闲置 24 小时的实测。

首次扩大回归发现放大全局帧上限会改变旧档案预览阈值；已改成 Host 通道独立上限，并保留首次失败输出 `full-backend/tests.log`。修复后 `apps/host`、`internal/protocol`、`internal/transport` 全套复测通过；此前已通过的 `internal/configjson`、`internal/configuration`、`internal/settings`、`internal/ai`、`internal/host` 结果仍对应未变化实现。以上八个包的静态检查、MyGo 设置窗口全部默认测试及仓库边界检查通过。

本次不运行联网、真实用户安装或系统交互验收；没有读取或改写真实 WinOne 配置。最后的交叉检查补充了“后台刷新失败后手动获取成功”的回归，旧实现可复现将过期错误写回，已修正。为包含此修正，停止了尚未完成的候选安装器压缩，候选文件保留；补测中的一次串行命令达到 60 秒执行上限，已经通过的 AI 包结果保留，Host 与页面检查独立续跑并通过，AI/Host 静态检查通过。完整构建及固定安装器交付结果另行补记。
