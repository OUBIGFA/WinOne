## 首页的职责

首页回答两个问题：有哪些工具可用、哪些工具需要启用或处理。工具名称、用途和启用开关组成独立分区。正常状态使用低强调文字；只有异常需要提示用户处理。

移除快捷键汇总、启动设置摘要、大号统计与可拖动的状态分栏。快捷键在各模块顶部设置，启动方式和权限在全局设置中管理。首页不复制这些内容，也不增加没有实际任务的图表、欢迎标语或活动数据。

## 统一规则

- 组间距离大于组内距离。常用组间距为 24–28 px；字段之间为 20 px；字段名称与控件之间至少 6 px。说明与对应名称可更紧凑。
- 用布局的 gap 维持分组，不依赖可能被旧规则清零的标题外边距。功能样式先声明共同 CSS 层级顺序，避免导入顺序改变优先级。
- 主标题、分组标题、字段名称、次要说明分层；不靠全加粗或把说明缩得很小来区分。
- 文案先说明动作与结果，保留必要条件。一处只讲一个意思，不重复展示“先保存”“再获取”等引导。
- 编辑器按需展开。折叠、排序和切换标签保留草稿；保存成功才清除未保存状态。
- 双列表单按实际内容区宽度变为单列。标签栏可换行；长名称和路径按对应区域换行或省略，不产生横向滚动条。
- 普通操作不使用错误色。错误说明与操作分开，保存、撤销和删除保持清楚的操作边界。

## 账号流程去重与原位命名（2026-10-07）

用户指出新增账号时选择智能体、详情再选择智能体存在重复，随后要求把“服务名称”并入“服务”。原来的新增按钮创建独立连接，详情下拉框则修改当前连接类型；两个入口使用同一目录，又被“登录或添加账号”的文案混为同一任务。仅检查控件是否可见，不能发现这种操作职责混淆。

最终流程为“添加账号 → 选择账号类型 → 登录 → 勾选模型”。详情仅显示平台身份，不再提供第二个类型选择框。未登录显示“登录”，已有账号显示“重新登录”；服务确有多种授权方式时，继续显示“登录方式”。添加第二个账号仍使用独立连接，旧账号名称、模型及全局任务引用保持原值。

服务与账号的名称统一在顶部选择区域编辑：点击铅笔，原位置改为输入框并选中名称；回车、勾号或移开焦点结束输入，Esc 恢复本次编辑前的名称。输入即时进入页面草稿，保存与未保存保护继续使用既有机制，不自动写入配置。新增空白自定义供应商直接进入命名。移除了详情中重复的名称字段及账号页空的连接设置分区。

交互采用本项目《统一体验与设计依据》的操作职责明确、渐进呈现和键盘焦点原则；组件继续复用现有 Input、Button、Select 和 Lucide。此次不改变 Host 的账号协议、凭据隔离和模型分配结构。

验证：重复类型选择和独立名称字段的两项回归均先复现失败，再通过；当前前端共 339 项通过，最终相关 24 项与 TypeScript/构建复验通过。6 组浏览器流程覆盖类型只选一次、取消添加、键盘选择、原位改名与 Esc、登录、保存模型、第二账号隔离及切回原账号。另通过 32 个登录状态、56 个菜单组合和 4 组侧栏/缩放/草稿检查。设置使用内存模拟桥接，未登录用户真实账号。
