# OneBot 首次打开提速（2026-11-08）

首次切换会按需启动 OneBot 独立进程。原实现通过顶层导入加载五种消息平台和 Pi 的完整导出入口，即使只是读取空队友列表。瓶颈主要发生在进程开始接收请求之前。

## 改动

- `modules/chat-pi/onebot/im-service.mjs`：创建连接时才加载对应平台，保持同步创建和原有暂停、恢复、退出顺序；五种平台全部保留。
- `modules/chat-pi/onebot/history.mjs`：有实际历史文件时才加载 Pi 的 `SessionManager` 实现。入口直接对应固定 Pi 1.5.0 公共导出中的同一模块，不复制或重写历史解析。
- `modules/chat-pi/onebot/runtime.mjs`、`host-client.mjs`：技能和插件资源检查在打开相关功能或创建队友时才加载。
- 未增加依赖、常驻进程、启动预热或延时画面。账号、数据、权限与功能入口不变。实施前查询 npm，Pi 最新正式版仍为固定的 1.5.0。

## 性能证据

同一电脑、Bun 1.4.2、相同构建入口，各启动五次新进程，每次使用新建空配置。依次请求 `init`、`profiles.list`、`bots.previews`、`groups.list`，每次正常关闭进程。

| 指标，中位数 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 进程启动至协议就绪 | 1372.11 ms | 516.23 ms |
| 进程启动至初始化完成 | 1485.50 ms | 609.50 ms |
| 进程启动至首页数据返回 | 1569.95 ms | 643.79 ms |

首页数据阶段减少约 **59.0%**。这是运行进程与数据加载测量，不是鼠标点击到最终绘制的完整时间，也不是清空操作系统文件缓存的冷启动。真实账号、大量队友和长历史不在此性能样本中。

可复现入口为 `build/benchmark-onebot-startup.mjs`，参数依次为 Bun、构建后的 `onebot.js`、仓库 `_temp/` 下新输出目录和次数。真实桌面检查 `tests/native-ui-matrix/run.py` 增加了首次切换到首页按钮可用的测量点。

## 检查与限制

- 新增导入拦截回归：让未使用的执行库不可加载，旧实现因提前加载 Pi 失败；修改后空首页可正常读取并退出。
- 新增五种真实消息平台的按需初始化与退出检查，使用原有连接存储和无凭据状态，不替换平台工厂。
- 完整构建中的 OneBot **122 项**运行测试通过；真实 Host、OneBot、Pi 与隔离模型服务之间的 **28 项**联动测试通过。历史、资源检查、群聊、权限、语音、持久化及退出回收均由既有回归覆盖。
- 统一完整构建、桌面全量测试、普通及生产静态检查、产物与许可校验通过；完整包校验 **6086 个文件**。
- 修改前的真实桌面首次切换记录为 3115.66 ms（单次，含自动化调用开销）。窗口群组及自动化操作通过；后续设置组件检查在姓名输入框点击定位处失败。该检查使用修改前运行库，不能记为新版验证通过。
- 用户随后要求不再弹出联网测试授权。所有本任务测试进程已退出，不再启动可能触发该授权的测试；因此未取得修改后的完整桌面切换对照，不将后台测量写成整窗提速比例。
- 首轮隔离覆盖安装超过测试脚本 120 秒时限，产品随后报告置顶模块启动自检超时并回滚。保留原始失败证据；改在独立测试桌面运行相同安装包，将测试脚本的整次操作等待设为 300 秒，产品自检时限与条件不变。复验覆盖安装以退出码 0 完成，实际耗时 238.215 秒；这不是安装速度优化结果。
- 最终隔离首装、覆盖、卸载全部通过，6086 个文件哈希、登记、快捷方式、配置及额外文件保留均通过。没有重测修复安装、历史恢复及卸载中断矩阵；没有在用户要求停止后新增联网授权测试。
