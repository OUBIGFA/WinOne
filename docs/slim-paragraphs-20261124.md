## OCR 行为与来源

已核对调研时 Umi-OCR 最新主分支 `83173efc4f4453b41223ea96d63d44534bf0505c`，复用其 `parser_tools/gap_tree.py` 和 `paragraph_parse.py`。前者按连续空隙划分阅读区域，后者先匹配段落主体的左右边缘和行距，再把缩进首行、较短尾行归入邻近段落。许可为 MIT，原文、提交和适配文件摘要进入 `third_party/import-notices.json`。[Umi-OCR 对应源码](https://github.com/hiroi-sora/Umi-OCR/tree/83173efc4f4453b41223ea96d63d44534bf0505c/UmiOCR-data/py_src/ocr/tbpu)

Text Grab `f0345015dcabf572453568addfcecc64abfc1c16` 的 `MakeStringSingleLine` 和 `JoinLines` 也已核对。其通用文本换行替换适用于人工整理，自动段落判断采用带几何信息的 Umi-OCR 方案。[Text Grab 对应源码](https://github.com/TheJoeFin/Text-Grab/blob/f0345015dcabf572453568addfcecc64abfc1c16/Text-Grab.Core/Utilities/StringMethods.cs)

WinOne 的纯文本路径先按 GapTree 划分阅读区域，再沿用 HushSnap 行内排序、间距和 URL 保护，最后合并同段换行。中文连续衔接，英文词间保留空格，连字符和标点按原内容保留。大段距、字号变化、列表起点和代码保持相应边界。过窄空隙作为词间距，减少行内文字被误判成多栏的机会。上述附加条件是 WinOne 的适配选择。

纯文字输出由本地识别工作进程生成，截图识别并复制通过已有 Host 通道取得结果。原位路径只返回原始 `PinOcrLayout`，不调用段落合并。使用同一张生成图片验证，三行纯文本合并为一段，原位输出仍有三行及各自单字框。

这是一套几何启发式规则。非常规表格、混排和缺乏视觉边界的段落仍可能误分，不能保证从任意图片恢复作者的全部排版意图。保留 56 组旧排序回归、新增 14 组段落场景和 150 组块完整性场景，防止列分析丢字或重复。
