# 体积优化与 OCR 自然段复制

本轮按 2026-11-23 的体积核查实施运行库、语言、重复程序和随包文档精简，同时让纯文字 OCR 自动衔接同段的视觉换行。原位识别及原位翻译继续使用检测框和单字坐标。

## OCR 行为与来源

已核对 Umi-OCR 最新主分支 `83173efc4f4453b41223ea96d63d44534bf0505c`，复用其 `parser_tools/gap_tree.py` 和 `paragraph_parse.py`。前者按连续空隙划分阅读区域，后者先匹配段落主体的左右边缘和行距，再把缩进首行、较短尾行归入邻近段落。许可为 MIT，原文、提交和适配文件摘要进入 `third_party/import-notices.json`。

Text Grab `f0345015dcabf572453568addfcecc64abfc1c16` 的 `MakeStringSingleLine` 和 `JoinLines` 也已核对。其通用文本换行替换适用于人工整理，自动段落判断采用带几何信息的 Umi-OCR 方案。

WinOne 的纯文本路径先按 GapTree 划分阅读区域，再沿用 HushSnap 行内排序、间距和 URL 保护，最后合并同段换行。中文连续衔接，英文词间保留空格，连字符和标点按原内容保留。大段距、字号变化、列表起点和代码保持相应边界。过窄空隙作为词间距，减少行内文字被误判成多栏的机会。上述附加条件是 WinOne 的适配选择。

纯文字输出由本地识别工作进程生成，截图识别并复制通过已有 Host 通道取得结果。原位路径只返回原始 `PinOcrLayout`，不调用段落合并。使用同一张生成图片验证，三行纯文本合并为一段，原位输出仍有三行及各自单字框。

这是一套几何启发式规则。非常规表格、混排和缺乏视觉边界的段落仍可能误分，不能保证从任意图片恢复作者的全部排版意图。保留 56 组旧排序回归、新增 14 组段落场景和 150 组块完整性场景，防止列分析丢字或重复。

## 交付方式取舍

Bun 和精简后的 .NET 继续随包交付。本次选择保留现有首次运行和离线使用方式。按需下载只能转移这些依赖的获取时间，干净机器仍需要获取它们；Bun 还供 45 个账号插件和完整连接粘贴解析使用。没有引入自动下载流程或改为依赖机器上的预装运行库。

PP-OCRv6 small 两模型和学习词典继续提供现有质量与词条。上一轮词典空闲页为零，构建已执行压实。更小 OCR 模型或量化尚无同质量证据，本轮减重来自程序、依赖和交付内容。
