# 共享依赖设计

2026-10-08，源码、实际 Host 流程及原生界面通过相应验证；用户最新要求暂不构建，整包与安装器验收已停止。目标是完成既定模块契约中的共享运行时与依赖保护，不改变 WinOne 当前安装器或界面技术路线。

## 选型与依据

| 方式 | 影响 | 决定 |
| --- | --- | --- |
| 所有模块共用一个可覆盖目录 | 更新可能改变仍在运行的模块所读取的文件，回滚也可能覆盖其他模块需要的版本 | 不采用 |
| 分版本不可变目录，加明确的依赖锁定与引用检查 | 可并存旧、新版本；卸载和回收能分别检查安装引用与运行占用 | 采用这条实现方向 |
| 直接把扩展改成系统 MSIX framework packages | 需要增加另一套系统部署、登记和权限边界，会扩大当前安装路线 | 不在本阶段引入 |

Microsoft 的 [framework package 维护模型](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/framework-packages/framework-packages-overview)分别跟踪安装引用和运行引用，并允许版本并存。这里只借鉴生命周期分工，不声称 WinOne 自有包已经具有 MSIX 的系统保障。

[NuGet 锁文件](https://learn.microsoft.com/en-us/nuget/consume-packages/package-references-in-project-files#locking-dependencies)记录已解析的依赖；锁定模式不能满足原记录时应失败。WinOne 的锁定还须绑定已经验证的发布者、清单摘要、平台和具体文件，不能只按包名或版本推断内容相同。

## 需要保持的规则

1. 模块包与无独立界面的共享运行时包区分，不为运行时伪造 Worker、开关或设置页。两者继续使用已有签名、大小限制、暂存及恢复边界。
2. 每个模块的依赖图解析为明确身份、版本及清单摘要；缺失、冲突、循环或签名失败在登记前指出。运行时不临时换用另一版本，也不从任意网页补装软件。
3. 同一个共享包版本只保存一份内容，不同版本并存。模块更新期间，旧依赖仍服务于旧进程和回滚；提交后才释放不再需要的安装引用。
4. 安装引用来自有效模块记录和待处理事务，不以易失的内存计数代替。运行中的依赖继续使用文件句柄保护，最后一个实际使用进程退出后才能释放。
5. 卸载一个模块不删除其他模块需要的运行时。回收前同时检查完整依赖引用、待恢复事务、运行占用和文件完整性；异常保留并给出处理入口。
6. 依赖路径只传给对应 Worker，不能改全局 PATH、系统运行时登记或其他软件配置。加载仍由审核后的模块代码执行，进程隔离不作为恶意代码沙箱。
7. 工具管理复用现有安装确认、版本及清理反馈。依赖信息放在对应模块的详情中，不增加独立常驻 UI 或新的全局任务页。

## 实施顺序与验收

- 先明确模块/运行时身份、依赖锁定格式与兼容读取，再接暂存登记及失败恢复。当前安装准备记录和遗留检查作为共同前提。
- 接通按需加载、安装引用及实际进程占用；验证两个模块共享同一依赖、一个模块关闭或卸载时另一个仍可使用，以及新旧依赖版本并存。
- 接入现有安装界面和整包升级预检；验证缺依赖、循环、内容变化、中断、回滚、离线重开、卸载及资源回收。使用实际签名包和 Worker，不能只用图算法单元测试宣称完成。

## 当前格式与接入

`module.json` 的元数据 v4 用 `kind: module | runtime` 区分模块和共享依赖。模块继续使用已有 `module`、配置定义和按需 Worker 契约；共享依赖使用 `runtime`，只声明双语名称和文件或目录导出，不声明 Worker、开关或配置页。包格式分别为 `winone.module.v1`、`winone.runtime.v1`，都使用现有签名、清单、许可证和载荷校验。

每个 `dependencies` 项包含 `kind`、`id`、`version`、`manifestSha256`。不解析浮动版本，不自动下载缺失内容。直接依赖最多 64 项，传递闭包最多 256 项、深度最多 32；缺失、内容变化、循环、版本冲突和平台不兼容均拒绝。v1–v3 模块保持原来的解释。

| 对象 | 实现与边界 |
| --- | --- |
| 依赖解析 | `internal/modulepackage/dependency_graph.go` 形成完整 `DependencyLock`；摘要绑定根包、平台和每个精确依赖 |
| 分版本库存 | `packages/shared-runtimes/.winone-runtime-registry.json` 按签名清单摘要登记；同版本不能换内容，不同版本并存 |
| 安装引用 | 来自已登记模块、共享依赖以及未完成事务的前后版本；普通模块的更新或卸载也检查反向引用 |
| 运行占用 | 每代 Worker 单独持有依赖文件与祖先目录句柄；实际进程退出或启动失败后释放，不以易失计数替代文件保护 |
| 本次调用上下文 | 只向带依赖的 Worker 增加 `--dependency-context <本模块数据目录/dependencies.json>`；旧 Worker 参数不变 |
| 失败与回收 | 复用准备账本、签名内容检查和回收站后端；文件占用或身份不符保留待清理状态 |
| 设置界面 | 复用安装、卸载确认组件；模块详情可展开依赖，工具管理列出共享版本、使用者及卸载状态，无额外开关 |
| 整应用升级 | 配置指纹纳入共享库存和清理账本；兼容检查覆盖已安装依赖。没有共享数据的旧配置保持原指纹契约 |

上下文 schema 1 包含 `root`、`lockSha256`、`hostPipe`、`packages`。每个包位置包含精确身份、实际 `directory`，共享依赖还包含已转换为绝对路径的 `exports`。上下文最多 1 MiB；只写入 Host 的模块数据目录，并拒绝包目录、目录联接和重解析路径。上下文文件也保持只读句柄，Worker 不能将其当作永久缓存或用于改变其他模块的依赖。

共享依赖没有独立启动过程；经过审核的 Worker 决定如何使用导出文件。模块依赖只提供已锁定的包路径及 Host 通道，不隐式开启另一模块，也不绕过该模块的启用状态。

## 已有证据与未完成项

定向签名、图解析、并存存储、引用保护、文件占用、目录联接拒绝及真实 Worker 测试通过。实际 Host 首轮流程通过，补充失败候选恢复后，37.54 秒的完整流程复验通过；覆盖缺依赖拒绝、两模块共享、单模块切换依赖、候选退出失败后恢复旧依赖、离线重开、逐个卸载及完整进程组退出。卸载测试故意持有文件，验证保留待清理状态；本阶段没有重跑成功移入系统回收站的测试。

Go 源码范围回归通过。前端首次完整运行有一项 AI 密钥设置测试超时；不改门槛、独立复验后 369 项通过。Rust 候选构建及 8 组原生界面矩阵通过，保留既有编译警告。随后按用户要求停止构建，只修正引用错误提示、重复扫描和版本排序，34 项相关前端测试、TypeScript、包管理与 Host 回归及 vet 通过。这批收尾修改没有重新构建；本轮没有生成并验收新的固定安装器，其他任务更新的产物以其各自记录为准。

管理页通过 `ReferencesFor` 在一次查询中扫描各声明一次，只收集指定版本的使用者。结果不跨操作缓存，卸载时仍重新验证当前引用和信任。引用查询失败时只显示错误，不将未知状态描述为“无人使用”。
