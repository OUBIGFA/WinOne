# Chat、AI 路由与文件分享打磨

## 目标与设计

恢复 Chat 新建对话此前 160 DIP 的完整 Logo，Logo、项目选择和输入区作为一个整体在可用区域居中；低窗口可以纵向滚动。

AI 路由以用户命名的路由组为主要列表，显示供应商名称、模型名称、策略和可用状态。内部 UUID 只用于请求与保存，不进入列表、选择器、提示或辅助功能名称。模型别名、嵌套组、思考档位和未知模型仍可区分。自动发现、模板与默认设置分组收纳，完整保留全部能力。

文件互传和云端分享在没有文件时显示拖放入口；添加文件后，主体变为文件列表，优先显示文件名，完整路径留在次级说明和提示中。添加文件、文件夹、粘贴与清空收为同一工具栏，发送操作紧接文件列表。沿用现有服务、收发选择及真实传输执行。

采用当前原生 MyGo 组件和 WinOne 设计系统，不更换框架。仅处理内部标识文本不足以解决列表层级；另建路由或文件管理系统会扩大任务，故调整现有展示与分组。

## 用户指定的设计审核方法

后续审核同时覆盖 AI 路由与互联助手。参考来源为 [Impeccable 4.8.0](https://github.com/pbakaus/impeccable/tree/687bc381bc9091bf252c0a05303640561014a425) 的 Operate、polish、craft-floor，以及 [Unslop](https://github.com/heydamir/unslop/tree/a6f121eee5f29c2f74976b75456feae8b66afb3a) 的 spacing → color → icons → copy → type → layout → details → visuals → motion 顺序。Unslop 作者 Damir Sokolovsky（@heydamir），CC BY 4.0。仅采用设计方法；未安装全局技能、执行第三方启动脚本或上传截图。Impeccable 自动上下文程序未运行，直接使用已有项目约定与生产组件截图；Windows 原生界面不使用网页 DOM 检测分数。

设计方向：
- 产品：让用户配置 AI 请求去向，并把选中的文件发送或分享出去。
- 性格：平静、明确、可靠。
- 视觉来源：Windows 桌面工具，沿用 WinOne 的字体、黑白主操作与 Lucide 图标。
- 内容重点：路由组名称与成员；已选择的文件名与发送状态。
- 一致细节：主体列表左对齐，主操作明确，完整路径与辅助操作降为次级。

改前审核发现：
- P1：正常路由视图直接展示 UUID 与组合引用，用户不能据此分辨模型。以模型名、供应商名称替换展示，保留真实请求标识。
- P2：组列表每行重复显示六项操作，成员信息被操作栏打断。编辑与启停保持可见，其余操作进入有辅助功能名称的菜单。
- P2：成员选择区固定高度造成空白，英文页签截断。列表改为内容高度加最大高度，页签使用短名称。
- P2：文件已选后仍保留空态提示与多项并列添加操作。空态转为文件列表；添加文件保留可见，文件夹、粘贴与清空仍可从菜单使用。
- P2：文件区的计数、文件名、按钮和发送说明缺少共同对齐。建立统一列表起点，发送按钮对齐列表末端，保留云服务限制说明。

没有发现渐变、装饰动画、表情符号图标或卡片套卡片问题；不为套用风格新增插画、色彩或页面系统。后续以中英、深浅色、1000/560 DIP 和实际交互复核，不把审美分数当作功能通过证据。
