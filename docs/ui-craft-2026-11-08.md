# WinOne 全局界面重做与验收

## 目标和范围

用户要求全局审核和优化，允许推翻原有布局，以成熟桌面软件、尤其 Claude Code 当前桌面端为参考。覆盖共享外壳、设置、Chat/OneBot/闪聊、AI 服务、文件与程序管理、结果窗、截图工具及保留的网页界面。保留全部功能、入口、数据、配置、快捷键、权限和未保存保护。仅使用仓库内隔离运行环境。

必须完成至少三轮审核，三轮均无未解决问题，才可交付并更新 `dist/release/WinOne-setup.exe` 和 SHA-256。发现问题的轮次只算发现与修复，不能计为无问题轮次。提交和推送放在所有改动和验证完成之后。

## 设计决策

产品：将 Windows 工具、AI 工作和跨设备任务放在同一个桌面入口。

气质：沉静、准确、易于长期阅读。

视觉基础：近中性的纸白与石墨；颜色留给内容、提供商身份和确有含义的状态。Windows 系统字体与本地线性图标保持平台熟悉感。

重点：任务内容与输入框。设置用清楚的分区和对齐，Chat 用可读的消息列与紧凑的项目会话导航。品牌标记保留，但不占据主要工作空间。

一致细节：方正中带小圆角的动作控件，少量互斥选择直接可见，侧栏选中采用中性底色，焦点与悬停各有可观察状态。

选择原生框架内的全局重做：共享主题和组件一起调整，再处理各工作区。单纯换色无法解决层级；更换整个运行框架会增加性能和兼容风险，不能帮助本次任务。现有功能行为及兼容接口保持。

## 初始审核

基线截图来自真实生产页面组件，位于本次忽略目录。组件截图不能代替完整窗口验收。

1. 设置分区依赖大量圆角面板，每组的外框与控件边框争夺注意力。
2. 页内标签与组标题近似同级；共享外壳没有内容区页标题。
3. 外壳导航 44 DIP 行高与 Chat 导航密度不一致；选择条、底色和加粗叠加。
4. 暗色侧栏比内容亮；导航与文字缺少清楚的主次。
5. 设计色值在设置与结果窗重复维护，容易漂移。
6. 部分小字、间距和圆角各自定义。需检查中文、英文和窄窗，不能只验证宽屏空状态。
7. 基线截图中文字呈现需与真实窗口核查，不能把测试渲染差异直接当作生产字体错误。

## 发现与修复记录（不计无问题轮次）

- 组件迭代：窄窗标签压缩、Chat 输入框首帧跳动、下方工作区挤压消息区。修复后定向测试通过。
- 完整回归：结果窗两项旧图像测试假定纯灰色背景。改为验证共享背景边缘和单一前景色混合，保留彩色供应商图标与可见性检查，没有改变图标渲染行为。
- 整窗迭代：程序管理首次窄窗尚未测量就使用左右布局，空态提示按固定偏移显示。新回归先观察失败，改为实际空间居中后通过。
- OneBot 首次打开的加载指示贴在内容左上角；改为内容区居中并复用“正在打开 OneBot”中英提示。
- 截图工具栏：1172 与 320 DIP、工具溢出、动作溢出和样式菜单核对通过；六组显示区域几何检查通过。
