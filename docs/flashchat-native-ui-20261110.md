# 闪聊原生界面

用户要求移除产品界面里的上游版本、地址及 GitHub 信息，全部可见界面使用 MyGo。用户确认继续复用后台浏览器通信引擎。

## 布局重做与参考

用户否定第一版的布局和层级后，本轮重新阅读并查看了 [Slack Design 的官方设计说明和界面截图](https://slack.design/articles/a-more-focused-productive-slack/)。采用其会话列表与正文分栏、按任务组织工具、合并输入区的思路，不复制代码或图片资产。字体、灰阶、组件与设置分组沿用 WinOne 的共享 kit。

- 大厅以“昵称 → 房间 → 进入”为主路径。社区房间放在次要区域，窄窗口收为入口。
- 聊天左侧固定 264 DIP，容纳群聊、私聊、摘要和未读数；个人设置放在底部。
- 正文页头只保留当前会话、成员数与音视频操作。邀请、设备、全屏、设置和退出归入“更多操作”。
- 消息统一按头像、作者、时间、正文排列；输入与附件、按住说话、发送合并成一个固定区域。
- 窄窗口在会话列表和正文之间切换，消息、工具和输入区不横向挤出。
- 设置按个人信息、消息提醒、网络、资料分组；使用原生分组、开关、选择器和对话框。

YouTube 地址显示原生“打开视频”按钮，在默认浏览器播放，这是用户明确确认的替代方式。文件媒体和实时通话继续在原生窗口呈现。

## 实现边界

- 原生大厅、会话侧栏、消息、输入栏、设置、成员、身份、公钥、分享和确认弹窗使用已有 MyGo / kit 组件。
- 隐藏 WebView 保留原有身份存储、ChatRoom、Trystero、加密文件传输和媒体采集。界面通过限定的命令和状态接口接入；不向通信引擎开放通用 Host 或磁盘权限。
- 视频帧由隐藏引擎解码，MyGo 图像组件呈现；音频由原引擎播放，按钮、设备选择、音量和播放控制由原生界面提供。
- 文件选择、资料导入导出使用宿主文件选择器；后台只可读取用户本次选择并授予的文件。
- 原有存储位置、公开及私密房间语义、私聊隔离、历史补发、媒体与文件操作、切页保持及关闭释放全部保留。
- 产品帮助只描述闪聊使用方法。源码与许可证记录保留在仓库和发行许可文件中。
- 邀请携带房间坐标，收件人在闪聊的房间输入框粘贴；不依赖上游网站。嵌入代码需填写自己的 HTTPS 页面地址，私密邀请不生成只支持公开房间的 SDK 示例。
- WebView2 的后台调度与自动播放策略从第一个页面起设置，避免先打开其他功能后，闪聊隐藏引擎无法持续工作。页面不可见时暂停视频帧编码，关闭窗口释放引擎和本地端口。
- Chromium 会延后从未显示过的页面中的文件媒体加载，后台计时器和自动播放开关无法改变这条路径。引擎使用 1 DIP 绘制区域，始终被不透明原生页面覆盖并禁止输入；网页内容设为 inert、aria-hidden，不挂载网页大厅。Windows 辅助功能仍可能枚举到空文档容器，但其中没有可读内容或可操作控件。依据为 [Chromium 媒体延后加载实现](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/no_state_prefetch/renderer/no_state_prefetch_utils.cc)。图片使用离屏解码，避免等待隐藏页面的绘制周期。
