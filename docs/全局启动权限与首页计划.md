# 全局启动、权限与首页

更新：2026-10-01。正在实施，未全部完成。

当前状态：普通登录启动、静默启动与旧偏好迁移已实现；首页已移除重复导航，加入工具启停、快捷键和启动状态总览。真实管理员授权、统一重启及退出后沿用授权启动已验证；界面、Host、三个模块均核实取得管理员权限。真实登录、撤销授权和卸载仍待实机验收。

## 已确定的产品行为

- 全局设置提供“登录 Windows 时启动”“静默启动到托盘”。WinTray 仅保留所管理程序的启动设置。
- 普通自启采用当前用户登录触发的计划任务，`InteractiveToken`、`LeastPrivilege`，不配置延迟、不要求管理员。实际启动时刻受 Windows 调度影响，不承诺零毫秒。
- “以管理员身份重新启动”作用于整个 WinOne；“始终以管理员身份运行”首次请求 UAC，注册当前用户专用的高权限任务，后续沿用授权。取消授权保持原模式。
- 管理员模式统一覆盖 Host、UI 与按需启动的三个模块；已有进程必须经过恢复、退出及交接后重启，不能只提权界面。
- 关闭持久管理员模式撤销授权任务；安装更新、移动安装位置和卸载必须同步处理任务。授权不写入可迁移配置，普通账户不能凭导入文件获得权限。

## 首页

首页承担状态总览与工具启停，不重复侧边栏导航。

1. 顶部用清晰字号展示总体状态和已开启工具数量。
2. 显示当前生效的快捷键，冲突或故障优先提示。
3. 工具管理展示名称、简短用途、开启状态和开关，移除所有“进入模块”按钮。
4. 展示实际登录启动和权限状态；需要处理的问题才出现操作提示。
5. 不放虚构统计、使用次数、推广内容或重复设置。未来工具增多时按启用状态分组，不让首页成为第二份导航目录。

## 实施顺序与验收

1. **全局启动归属**：脱离 WinTray 运行状态；保存失败回滚、重启恢复、模块禁用后仍可自启、导入旧偏好。
2. **统一权限**：固定任务动作与用户身份；首次授权、取消、重复启用、恢复普通模式、全进程权限验证；不关闭用户其他程序。
3. **首页**：状态、快捷键、工具启停和启动/权限概览；中英文、窄屏、长文案、键盘和异常状态验收。
4. **交付检查**：任务注册与卸载、普通/管理员启动、托盘显示、三模块运行和资源回收；未做实机验证的项目如实保留。

当前第 2 项已实现：

- 授权任务及 UAC 辅助入口：固定当前账户、程序和参数；取消或账户不一致时不改变当前运行状态。
- 管理员启动入口：区分手动与登录启动，等待旧普通后台和窗口退出；不把任务受理当作进程就绪。
- 重启准备协议：异步准备、取消、30 秒确认超时和交接失败恢复；令牌绑定实际发起进程。
- 管理员辅助进程确认：核对同一安装目录、账户和实际提权状态；确认绑定同一次重启，原窗口不能冒充替换进程。启动辅助程序已参与确认，回包丢失时保留已收到的提交结果。
- 进程身份检查：从 Windows 获取管道双方 PID，核对路径、账户和令牌；识别检查期间退出的进程，不信任 JSON 中填写的 PID 或权限。

上述代码、真实管道和独立子进程测试及静态检查通过。真实授权、重启、退出后重新启动均已验证；后台及各模块实际权限核对记录位于 `_temp/admin-xml-fix-1001/`。

原生管理员重启调用已串联授权、准备、辅助进程确认、提交及关闭原窗口。旧 Host 只有在原窗口退出且辅助进程确认后才结束；超时或辅助进程退出会恢复后台并打开 WinOne，显示运行警告。相关顺序、取消、失败恢复和重复提交回归通过；正常授权重启路径已实测，故障恢复尚需完整实机覆盖。

持久偏好与全局权限按钮已接通，置顶面板的独立权限入口已移除。启动沿用现有授权；授权失效时以普通模式启动并提示。关闭持久管理员模式可撤销已有授权，导入配置保留本机权限偏好。

后续三步：

用户当前选择保留管理员授权；不执行撤销授权测试，也不为继续验证而重复询问。测试包沿用原路径更新，避免因换目录触发重新授权。

1. 正常授权重启与三个模块实际权限已验证；继续覆盖取消及故障恢复。
2. 退出再开已沿用现有授权取得管理员权限；继续验证静默登录、重复打开、授权失效及恢复普通模式。
3. 验证安装更新、卸载清理与进程回收；完成前不将管理员模式标为已验收。

实现约束：普通登录任务保持单实例；管理员按需任务允许并行受理，由产品启动检查避免重复后台。撤销入口只删除自身授权。启动与授权受安装维护锁保护；任务受理不能代替后台就绪验证。

接口依据：[RegisteredTask.Run](https://learn.microsoft.com/en-us/windows/win32/taskschd/registeredtask-run)、[ExecAction.Arguments](https://learn.microsoft.com/en-us/windows/win32/taskschd/execaction-arguments) 支持固定启动入口的模式参数，但受理不代表启动成功；[GetNamedPipeServerProcessId](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeserverprocessid) 用于核对真实后台身份。

## 调研依据

- [PowerToys 通用设置](https://learn.microsoft.com/en-us/windows/powertoys/general)：启动、外观、权限属于产品全局设置。
- [PowerToys 管理员模式](https://learn.microsoft.com/en-us/windows/powertoys/administrator)：区分本次重新提权与持续管理员偏好。
- [PowerToys DashboardPage](https://github.com/microsoft/PowerToys/blob/main/src/settings-ui/Settings.UI/SettingsXAML/Views/DashboardPage.xaml)：首页包含快捷键总览、冲突提示和工具管理。只采纳职责分配，WinOne 不复制模块导航按钮。
- [PowerToys auto_start_helper](https://github.com/microsoft/PowerToys/blob/main/src/runner/auto_start_helper.cpp)：计划任务区分普通与高权限运行。其 3 秒延迟不符合本次要求，WinOne 不采用。
- [Microsoft 任务安全上下文](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)：用户身份、交互令牌、最低/最高权限和注册权限约束。
- [Microsoft 导航原则](https://learn.microsoft.com/en-us/windows/apps/design/basics/navigation-basics)：一致、简单、清晰，避免重复路径。
- [Microsoft 字体层级](https://learn.microsoft.com/en-us/windows/apps/design/style/typography)：用标题与正文层级帮助扫描，不能仅堆小号控件。

以上资料于 2026-10-01 实际读取。WinTray 的登录任务实现已核对：当前用户 SID、登录触发、最低权限，无人为延迟。

首次实机授权发现 Windows 导出的任务 XML 会省略默认 `Enabled=true`，旧校验误报任务变化并导致辅助程序退出代码 1。已对照 [Microsoft Enabled 默认值](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-enabled-settingstype-element)修正省略值处理；显式禁用仍拒绝使用。新增回归先复现失败，修正后通过。修复包沿用此前授权完成管理员重启和退出后重新启动，任务最近运行结果均为 0。

注册检查与启动检查现已共用管理员任务字段校验。描述未变但动作、账户或权限已变化的任务，不再被当作可复用任务；用户明确重新授权时才能重建。相关回归已复现旧逻辑错误并通过修复后验证，未修改用户当前任务。
