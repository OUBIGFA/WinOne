# 模块启动与快捷键响应修复（2026-11-10）

## 根因与改动

所有按需模块的启动握手共用 `internal/modules/process_windows.go`。旧实现每次只给 `snapshot` 200 ms，再等待 50 ms 重发。客户端断开不会取消工作进程已进入的状态读取。置顶的状态读取包括窗口枚举；串行读取超过 200 ms 时，旧请求持续占用工作进程，新请求排队，最终误报“模块启动超时”。

启动失败后，`Lazy.Handle` 仍调用 `Process.Handle`，再次检查身份并执行原请求。因此用户看到失败后，原快捷键仍可能迟到执行。

- 启动检查沿用 8 秒总上限。只在监听端尚未建立时重试连接；一次已发出的状态请求在原预算内完成，不反复抛弃和重发。
- 工作进程退出会取消等待；服务返回的实际错误直接保留。进程身份检查、权限与正常退出恢复保持原路径。
- 启动失败时，发起操作和等待同一次启动的操作返回失败，不再继续执行。后续用户主动重试仍可连接已恢复的进程。
- 构建中的截图测试输出改放本次任务目录，避免残留测试程序占用共用 `bin` 文件而阻断后续构建。

## 验证

使用真实子进程和命名管道，状态读取固定为 350 ms。旧代码在 8.45 秒后报启动超时；修复后约 0.47–0.49 秒完成启动和首次操作，仅发出一次状态请求。取消测试在旧代码上仍返回操作成功，修复后正确返回取消。工作进程主动拒绝和中途退出的测试也通过。

最终完整候选包在独立测试桌面连续 5 次启动真实置顶工作进程，首次置顶为 140–225 ms，已启动后的取消置顶为 3–7 ms。每次核对 Windows 的置顶状态、关闭后的恢复和工作进程释放。此组关闭 DWM 边框，仅测状态及生命周期。

用户另行授权切换独立桌面 15 秒。最终完整候选包通过 `agent-desktop` 发送三次快捷键，核对置顶、取消、再次置顶，并通过 Host 的模块关闭请求确认恢复。包括测试命令启动开销的三次结果为 0.925、0.692、0.735 秒；不能把该值当作程序自身响应耗时。测试后输入桌面从 Default 返回 Default。

前两次物理输入检查的三次按键均成功，附加退出检查失败：私有桌面没有 Explorer 托盘，测试错误地假设托盘菜单可用。最终检查使用真实模块关闭协议，不以发送托盘消息成功冒充退出成功。

补充验证六项模块的启动、停用、快捷键释放和重启后停用状态保持，通过。旧验收脚本同时修正了三项过时假设：短暂配置占用只在明确拒绝且无副作用时重新申请；只核对本次停用的六项，其他 Host 内功能保持启用；无托管程序的 WinTray 可按设计在空闲三秒后退出，不能强制要求它一直驻留。生产启停逻辑不因测试修改。

复验入口：

```powershell
./build/test-source.ps1 -OutputDirectory _temp/<任务>/source
./build/test-module-startup.ps1 -BundleDirectory _temp/<任务>/bundle -OutputDirectory _temp/<任务>/native -RunSystemChecks
# 仅在用户明确允许短暂切换输入桌面时选择：
./build/test-module-startup.ps1 -BundleDirectory _temp/<任务>/bundle -OutputDirectory _temp/<任务>/hotkey -RunSystemChecks -ForegroundHotkey
```

这些数值是本机隔离样本，不是所有第三方窗口或清空文件缓存后的启动性能承诺。真实安装、用户配置和管理员授权未修改。

## 文件与目录链接的追加调整

恢复文件名和文件夹按钮的左对齐；按现有链接工作区的颜色区分类型：文件硬链接为蓝色、目录联接为紫色、符号链接为青绿色。来源、目标、待创建预览及类型标签共用同一配色，未确定类型保持中性底色。窄分栏允许类型和状态换行，避免挤压名称。

链接功能现有测试通过。使用真实 MyGo 页面渲染，检查了中英文、深浅色、1000/560 宽度下的已创建与待创建三类链接。截图保存在交付证据的 `links-shots/`。颜色只说明类型，不表示不同文件是同一个对象；路径与类型文字保留。
